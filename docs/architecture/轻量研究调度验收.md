# 轻量研究调度阶段

活动计划 research-script-dispatch-v1；前期基座和QQ证据独立保留。以下为验收定义，完成情况只记 progress.json，不把旧复杂分支图规划作为本阶段前提。

路径是有输入、结果验收和分支判断的可信小函数。研究协助负责选目标、开路、维修和取舍；研究任务执行已验证函数。原生会话/Inbox仍是任务与上下文的唯一所有者；不增加外层调度服务或模型循环。保留影视、音乐、杂项及额外功能推荐的既有分类，不自行增设会话；空闲自动启动保持关闭。

## S1-01 双分内核

- [ ] C01 参数匹配、最高分选择、失败重排和有效结果提前结束；全部本轮分小于零才耗尽，零分可执行，无固定重试次数上限。
- [ ] C02 历史分初始化本轮；单轮只更新一次历史分，历史有效轮数降低更新幅度；多次本轮失败不永久废弃稳定路径，版本分别积累。以可替换函数为评分单位，普通函数组合中下游失败不连带扣成功主干；经确认的负结果不当作方法报错。
- [ ] C03 原生Scope/KV/SQLite持久化、并发去重、重复请求冲突、重启不重放未知结果；停止、验证码和结果未知可中止，普通会话及其他模块保持可用。

默认权重为历史初始1、本轮失败扣2、轮末成功最多加0.2或失败扣0.1。历史调整再除以 sqrt(1＋历史有效轮数)，成功前的重试会降低奖励。所有路径比较的是本轮分，而不是执行次数。轮末报告一次写入，即为历史事实；历史分不因每次尝试被反复扣减。验证码、未知副作用、取消不用于推测路径可靠性；需要协助时保留卡点，不靠无限尝试解决。

## S1-02 原生协助与采集

- [ ] C04 原生研究协助先打通一条完整采集路径；首轮实际发现多个方向可标记候选分支入口，未验证前只提示、不参与评分执行。实际运行频繁报错后，才在错误点或更前面的合适位置开辟并验收同级分支，不为了分支故意设置节点。协助分配目的和参数，任务不自主选站、生成执行代码或探索未知分支。
- [ ] C05 同一原生输入拥有运行、取消和输出；同一研究轮内分支共用本轮分和轮末汇总，多次工具调用不能重置失败分或重复更新历史。有效主干输出绑定目标/参数、实现版本和有效性，局部失败复用有效结果，从最近有效位置恢复。阻塞带完整上下文交回协助，未确认副作用先核对；不创建第二套队列或通知风暴。
- [ ] C06 可信采集适配器的真实I/O验收和协助回路完成；真实网站权限/频率/登录另行验证，不能用合成数据冒充已开通。

## S1-03 产品接入

- [ ] C07 默认关闭的独立配置、启停和故障隔离；研究不依赖QQ在线。
- [ ] C08 紧凑展示当前目标、执行函数、卡点和双分选择依据；用户不必阅读代码，监控按需启动。
- [ ] C09 正式产品入口完整联调与回归，明确隔离验收和生产切换的差别；不重放旧研究任务，不擅自导入私人历史。

评分仅在真实可替换的同级分支内进行：category/action、输入输出与前置条件必须兼容；本段耗尽后向协助报告，或使用已存在且验证过的更早替代分支，不能现场探索。主干成功不因下游失败染红或扣分。只增加必要关联信息，不建设通用DAG引擎或外层队列。界面用虚线表示候选未验证分支，执行路径连续高亮，等待橙色、失败红色，代码和分数细节放详情；不把一次点击或日志行伪装成独立步骤。
