# OpenCode 基座实施约定

当前计划为 opencode-app-base-v2。先读重构方案，运行 next_task.py；旧 Python 宿主约定已经归档，不再把 Python、逐行 JSON-RPC 或旧包清单作为主应用的强制实现。

1. 使用锁定的完整上游源码和原生工具链，在 opencode/ 保留原 monorepo。自动化与数据处理优先 Python，不重写上游 TypeScript 核心。
2. 先建立未改造基线，再分开提交助手入口、权限裁剪、主题及能力适配。R0 核实命令，不凭旧 SDK 版本或旧目录猜当前 API。
3. 原生 Session/Inbox/历史/数据库/压缩/客户端状态沿用其所有权。助手业务不直接写这些私有表、不注册竞争调度器。
4. 先用原生插件、配置及GUI/RPC边界，缺口才做最小源码补丁。GUI实验接口需锁版本；不能以减少补丁为名把全部逻辑塞进另一个核心宿主。
5. 项目文件树与文件操作能力已确认移除，包括通用命令绕行。内部持久化、受控附件和业务文件服务保留；工具目录、实际调用及直接API都要验证。
6. 必要 Location 使用应用专属非项目环境，不发现真实用户工作区。未验证上游假设前不直接全局删 filesystem/数据库/迁移依赖。
7. 新数据、端口、账号配置和应用ID与旧助手及用户既有OpenCode隔离；不自动导入登录态、不修改正式自启。
8. 重负载能力独立服务或进程，拥有自己的数据与故障边界；无QQ、无业务模块、无API凭据也应能进入应用设置/空态。
9. 所有测试用合成身份和隔离数据。Python验收入口负责编排真实上游测试，不固定返回成功。缺少原生证据时记录未验证，不把旧49项测试搬作新版进度。
10. 每轮更新当前交接，完成状态只写活动 progress.json。R0未完成前，不编造原生构建命令已经验证、正式版本已经选定或源码已导入。
