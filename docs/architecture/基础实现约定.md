# 接手实现约定与待收口细节

本页给出第一次实现可采用的默认值和操作约定，不代表协议已在本轮扩展。已有接入单位与所有权保持不变；未决细节见 [决策记录](../handoff/决策与外部前提.md)，由对应任务同步契约、Schema 和测试。参数可以在有理由和测试时调整，不必为普通实现选择反复询问，但不能由模型输出随意扩大。

## 1 语言 目录与依赖

宿主和协议工具使用 Python 3.12 或更高版本，优先标准库的 asyncio、sqlite3、subprocess、unittest 等。结构验证使用现有 jsonschema 开发依赖。P0/P1 不引入额外 Web 框架、数据库服务或消息中间件；实际出现明确缺口时先记录替代方案和影响。

OpenCode 的 JavaScript/TypeScript 代码全部在未来的 `modules/opencode/` 中管理，后端有自己的包文件、锁文件和运行依赖。SDK 类型和版本以 [依赖基线](../handoff/dependency-baseline.json) 为起点；这是旧环境的版本证据，不是新仓库已经安装或完整验证的声明。

主程序预期启动入口为 `python -m host`，在 P1-05 完成前不存在。不要创建一个永远返回成功的占位启动器来通过验收。测试后端从 `tests/backend_fixtures/` 启动，不加入正式模块发现目录。

测试数据、临时目录和报告都置于仓库的 `runtime/tests/` 或 `.reports/`，遵守 .gitignore；不要固定依赖系统盘、原用户的盘符、已占用端口或旧项目环境。测试创建临时文件时显式传入本仓库测试目录。

## 2 连接与就绪状态

后端实例运行状态包括 stopped、starting、ready、draining、failed。连接状态另记 unconfigured、unknown、available、unavailable。后端管理门面 ready 不等于所有模型连接均可生成；没有 API 密钥时仍应能读取描述和配置。

托管进程只通过参数数组创建，不执行拼接的 shell 命令。`${runtime:node}` 是由宿主运行时目录解析的预留参数，不从模型、模块消息或任意字符串执行表达式。包入口及声明文件解析后必须仍位于当前包目录内，符号链接或目录连接不得绕过此限制。

`runtime.hello` 的请求至少包含协议、实例 ID、数据根引用和本次 `runtime_generation`。响应包含同一实例与世代、协议、backend ID、数据版本、运行状态和描述引用。实例或世代不匹配时拒绝接纳新变更。后续所有有副作用请求绑定这个世代。

后端不因宿主重连新建原生会话；恢复实例使用原数据目录和持久会话映射。外部服务模式仅断开连接，不默认关闭外部服务进程。

## 3 V1 stdio 协议

使用 UTF-8 的逐行 JSON-RPC 2.0，每帧一个完整 JSON 对象，以 LF 结束。不使用另一套 Content-Length framing，不在同一连接混用批处理数组。字符串中的换行按 JSON 转义。

stdout 专用于协议，日志写 stderr。非法 JSON、超长帧或 stdout 中夹入日志时，隔离该实例并给出可读原因，不把其他实例断开。单帧上限暂定4 MiB，按字节数检查，超过上限时在继续累计内存之前终止读取。

RPC id 使用方向前缀，例如宿主 `h-1`、后端 `b-1`；运行任务的 request ID 独立于传输 id。事件通过 `backend.event` 通知携带完整事件信封，通知没有 RPC id。双向方法均按已协商的白名单路由，收到事件不触发工具重执行。

I/O 读取与业务处理分离。读取循环先路由响应和通知，再让独立协程处理结果。事件积压上限暂定256帧；持续超限时关闭本次流并从已落盘游标恢复，不能丢弃关键事件后继续推进游标。来源事件持久保留由后端契约保证。

## 4 超时与重试

| 类型 | 首版默认 | 超时后行为 |
| --- | --- | --- |
| describe、列表、lookup、快照、health | 3秒 | 只影响该请求，可有限重查 |
| hello 与初始启动 | 20秒 | 标记实例启动失败，宿主继续可用 |
| 提交、调整、调序、取消等命令的回执 | 10秒 | 结果未知，使用原请求身份核对 |
| drain | 30秒 | 返回仍在途的具体原因，不自动强杀 |
| 长时间生成或事件订阅 | 无通用 RPC 总时限 | 由后端任务策略及明确取消控制 |

回执超时不能隐式转为 runs.cancel。只读查询首次失败后最多重试2次，间隔0.5秒和1秒；提交请求不被通用重试器自动重发。有限核对仍无法确定时保留 unknown，等待后端恢复事件或用户显式重查，不进行无期限高频轮询。

同一会话的转交保持输入顺序：上一输入已可靠接纳后，可以继续转交下一输入，无需等待上一任务完成。上一输入转交结果未知时，只暂停该会话后续转交以免乱序；其他会话不受影响。这是投递顺序保护，不是宿主的第二个执行队列。

## 5 RPC 成功和错误

成功响应沿用 JSON-RPC 的 result。协议错误使用标准解析、无效请求、方法不存在或参数错误码。业务错误使用 code=-32000，并在 error.data 中包含稳定的业务 code、request_id、retry_policy 与可公开 message。

```json
{
  "jsonrpc": "2.0",
  "id": "h-7",
  "error": {
    "code": -32000,
    "message": "原请求的接纳结果尚未确认",
    "data": {
      "code": "request_unknown",
      "request_id": "input-01",
      "retry_policy": "query_original"
    }
  }
}
```

相同幂等身份绑定授权主体、后端实例、操作和规范化参数摘要。规范化摘要保留内容语义，不通过删空白改变正文。不同内容重用同一 request ID 返回 idempotency_conflict；私密正文摘要不发布到全局日志。

## 6 必需方法的最小数据形状

| 方法 | V1 约定 |
| --- | --- |
| connections.list | 返回 items 与 next_cursor；连接含 id、revision、显示名、状态和可选能力，不能含密钥 |
| conversations.list | 返回 items、next_cursor 与来源水位；每项含稳定引用、标题、更新时间和原生状态 |
| conversations.open | 传 request_id、主体、连接引用与 create/attach 模式；返回稳定 conversation_ref；attach 只关联有权访问的原生会话 |
| history.read | before、after、tail 三选一；默认 tail=10，limit=1至100；返回消息及前后游标、stream_id 和 through_sequence |
| inputs.submit | 使用接口契约中的标准形状；持久接纳后返回 receipt_id、native_input_id、可空 native_run_id 与 execution_state |
| inputs.lookup | 返回 accepted、absent_confirmed、unknown 或 rejected；只有一致性范围明确的 absent_confirmed 才能再次转交 |
| events.subscribe | 输入不透明 cursor，返回来源流；重放事件保持原 stream_id、sequence、event_id |
| state.snapshot | 返回同一水位的会话状态、队列修订及来源 through_sequence；无事件的初始水位可为0 |

原生对象引用是长度受限的不透明字符串。不得根据它像某个 URL、路径或 UUID 就自行解析或访问。后端 queue_revision 也按不透明版本令牌进行相等比较，宿主不自行递增或按字符串排序。

宿主提供的 conversation_id 是稳定别名。后端由原生目录发现的已有会话，先按 backend instance 与 native conversation ID 的唯一映射登记，之后分配或复用该别名。不能因为宿主重新打开列表就重复建立会话。

## 7 消息与资源

V1 统一消息至少含 id、revision、role、phase、稳定顺序和适用的输入/运行归属。正文选择 text 或 resource_ref。`message.upsert` 采用相同 ID 的完整公开版本替换；宿主只应用更新修订，不重复拼接相同文本。暂不要求所有后端支持字节偏移式 delta。

资源引用属于待收口项 C02，当前 Schema 尚未声明 `resources.read`。建议在同一完整后端的门面内补齐受授权读取方式，例如有界分块；具体方法名、能力关联和大小需要由 P0-01 同步定义并测试。本次交接补充不添加这项接口，也不把它变成独立插件。

宿主将资源块提供给已授权的当前客户端，不把原生路径、任意远程地址或后端的访问密钥发给网页。跨会话、跨实例或过期引用拒绝。纯文本最小后端可以不声明 resources，并始终在帧大小范围内直接返回 text。

公开历史在后端保存。宿主只持有可重建缓存；上下文压缩不改变稳定历史顺序。清空会话、删除原生历史和移除宿主缓存是三种操作，不得用同一删除按钮隐式执行全部。

## 8 事件落盘与投影

宿主在自己的 SQLite 中至少保存实例和会话映射、输入投递、来源游标、来源事件、消息缓存及通知发件箱。后端的执行队列、原生上下文和压缩状态不进入宿主写入模型。

来源事件唯一键为 backend_instance_id、stream_id、event_id。消息缓存唯一键为 backend_instance_id、native_conversation_id、message_id。消息排序用来源稳定顺序，发生时间只用于显示，不用作唯一排序或去重依据。

同一次事务写入来源事件、可重建投影、通知待发项和游标。失败时不推进游标，不通知前端已经成功。最终消息已持久提交后再展示 run.completed；后端接着启动下一项不等待通知发送。

流中的 conversation_ref 必须与外层实例相符；宿主别名还要通过目录映射核对。runtime_generation 不参与持久事件去重：重启后的补收可能携带旧世代，不能全部丢弃。对新变更请求的过期世代校验与历史事件读取分别处理。

## 9 验证和进度

结构校验工具只验证规范与计划一致性。行为验证按任务中指定的测试文件运行，发现0个测试、文件不存在或导入失败都返回非成功。原生后端缺失时不能以跳过其全部测试得到绿色完成状态。

完成一个工作项需要产物、真正通过的行为测试、对应验收编号、验证命令与限制。progress.json 是已完成状态的唯一记录，work-plan.json 负责定义任务及依赖，最近交接只提供简短摘要，不再建立第二份独立进度列表。

当前各项仍为 pending。真实上游模型验证、原生窗口实机验收和上线切换需分别记录，不能用模拟夹具或设计检查替代。旧客户端的代码位置以本机不提交的定位文件为准，不要求公共仓库携带旧源码。
