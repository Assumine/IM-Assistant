# QQ 独立聊天插件阶段

活动计划为 qq-plugin-migration-v1，基于已完成的 opencode-app-base-v2。原基座10项任务、36项隔离验收和原证据保持原版本，不与本阶段完成率相加。定义在 work-plan.json 的 module_plan，唯一进度在 progress.json 的 module_plan；next_task默认选择 active_plan_id，运行验收可显式选择任一阶段任务。

本阶段接回独立小羊插件，延续[已确认边界](QQ接入与附属机器人边界.md)。协议是普通依赖；业务是两个独立可选插件。禁止反向依赖私有文件、全局替换发送、再造模型循环/Inbox/历史库，或用此阶段顺带搬入其他业务。研究、下载、设备、播放器与市场仍是后续阶段。正式入口、真实账号、自启、私人记忆迁移不在本阶段自动执行。

以下复选框只定义验收，不存放完成状态：

- [ ] B01 公共协议依赖可单独加载，任务转发使用同一实现；依赖不导入任务、人格、原生会话或其他业务私有源码。
- [ ] B02 认证双账号收发、同群身份、停止/断线/错误隔离、同进程账号唯一连接与未知回执不重放均由真实loopback验证。
- [ ] B03 提取后原任务转发、原生会话/Inbox/引用/图片和产品启动入口仍通过真实隔离回归。
- [ ] B04 聊天插件单独装配、独立故障/启停及模型配置，不依赖转发插件启动。
- [ ] B05 原生历史和记忆按插件、机器人、私聊/群隔离；群成员身份准确，重启仍成立。
- [ ] B06 人格和重复输入走公共原生会话接口，使用原生上下文/压缩/用量，不继承任务权限或再造队列。
- [ ] B07 聊天参与策略及回复开关独立，只读不回不触发发送，不把任务@规则套入闲聊。
- [ ] B08 来源、成员、结构化@、重复输入和发送回执准确；文本中的CQ不执行，未知结果不盲目重发。
- [ ] B09 受控图片、模型能力、授权表情及停用边界有真实证据，资源缺失如实报告。
- [ ] B10 产品入口实际使用独立账号/API/人格/回复设置，公开状态不泄露凭据，协议依赖不显示为第三个业务模块。
- [ ] B11 真实产品进程中只转发、只聊天、双账号共存、重启与单方故障均不影响原生会话和另一插件。
- [ ] B12 当前源码类型检查及受影响原生回归通过，记录源码和确切运行数；真实账号和生产切换保持另验收。

具体输入/输出、依赖、完成条件和运行入口均在任务定义中；待办不得因为原基座已完成而自动标记通过。配置与人格来源以现行有效需求及明确本地只读参考为准，不复制私人群历史或过去已取消的交互规则。
