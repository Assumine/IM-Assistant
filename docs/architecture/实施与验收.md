# 助手地基建设实施与验收

本清单用于建设隔离的新宿主与整套会话后端接入能力。当前状态全部为待实施；本轮交付方案及设计文件校验，不代表以下运行验收已执行。业务模块迁移另立任务。

本页定义验收，不单独维护完成状态。实现工作按 [任务分解](../handoff/work-plan.json) 的18项工作推进，实际完成记录写入 [进度记录](../handoff/progress.json)。旧客户端通过本地只读配置参考，无需上传公共仓库。

## 1 实施范围

本阶段新增隔离地基，保留生产系统、会话、账号、队列和业务模块。新版本不自动成为开机入口，不注册新 QQ 连接，不领取旧任务。测试采用新数据目录及明确测试会话。

实施过程中，发现当前代码不符合目标时先判断能否通过完整后端的适配层收口。不得为赶进度在宿主加入针对某个后端的专用分支，也不得把原生上下文和压缩工具拆成必装模块。

## 2 阶段 P0 契约与接入测试工具

交付：Python 侧协议类型、清单与描述验证、持久请求/事件测试驱动，以及两套内部结构不同的测试后端。

- [ ] F01 清单发现不导入模块代码，不发起网络或登录。
- [ ] F02 两个完整测试后端使用不同原生 ID、历史格式和上下文存储，均能通过相同接口接入。
- [ ] F03 测试后端内置的压缩、队列和工具保持内部所有权，宿主无法直接读写其私有库。
- [ ] F04 缺少必需方法拒绝加载，缺少可选能力仍能正常会话。
- [ ] F05 协议主版本冲突仅影响目标实例；未知可选字段不变成可执行代码。
- [ ] F06 同一个包可创建两个实例，数据、身份和事件流互不串用。
- [ ] F07 恶意或错误的路径、日志污染 stdout、超长消息、非法 JSON 均返回有界错误，不卡住宿主。
- [ ] F08 可选能力声明与方法集合不一致时拒绝启用该能力。

退出条件：相同测试驱动无需识别后端名称，即可完成列表、提交、历史、事件与恢复闭环。

## 3 阶段 P1 独立宿主

交付：单实例应用宿主、模块目录、运行进程管理、本机身份、配置、输入投递账本、事件投影、通知发件箱和基础界面连接。

- [ ] H01 不安装 QQ、AstrBot、Agent2API 和业务模块，宿主仍能启动与打开界面。
- [ ] H02 没有会话后端时展示明确空态，可读取配置与系统通知。
- [ ] H03 后端启动慢、启动失败、连接失败分别显示，不阻塞其他后端。
- [ ] H04 一个后端请求超时不占用 UI 或其他后端的事件处理线程。
- [ ] H05 本机身份不借用 QQ 白名单账号，外部主体不能伪造本机管理员身份。
- [ ] H06 配置带修订校验，保存后从实际消费者回读；明文密钥不出现在公开接口、日志和清单中。
- [ ] H07 只停止带有正确 PID、创建时间和实例身份的自有进程，不关闭共享外部服务。
- [ ] H08 维护实例 A 时实例 B 仍能接纳输入并完成；A 返回具体在途阻塞原因。
- [ ] H09 无需观测的页面不后台采样 CPU 或扫描所有模块；实例退出依靠通道和进程事件处理。
- [ ] H10 后端实际持久接纳前，宿主不显示“已排队成功”。
- [ ] H11 同一 request ID 重试返回同一回执，修改内容重用 ID 产生冲突。
- [ ] H12 后端成功接纳但回执丢失时，通过 lookup 找回原接纳结果，不出现第二次执行。
- [ ] H13 后端无法判断是否接收时，宿主保留 unknown；没有一个重试器自动改 ID 重发。
- [ ] H14 通知错误只进入通知记录；已完成的任务和最终结果保持。
- [ ] H15 消息未读与人工事项待处理分开，读完通知红点消失，但未处理的权限问题仍保留。

退出条件：移除所有测试后端后宿主继续正常运行；加入任一测试后端不修改宿主业务代码。

## 4 阶段 P2 OpenCode 整套参考后端

交付：独立后端进程，内部使用锁定的 OpenCode SDK、原生历史、Inbox、压缩和工具执行，并通过普通兼容 API 建立连接。初期保留2.1.4，升级需单独验证。

- [ ] O01 确认包名、版本、完整性及方法签名；不混用 V1 与 V2 SDK。
- [ ] O02 新建、重新打开和分页读取会话，映射到稳定的原生会话 ID。
- [ ] O03 不加载 Agent2API 插件也可配置普通 API；网关只是可选地址。
- [ ] O04 原生输入接纳产生真实 applied 事件；排队回执不冒充已读。
- [ ] O05 原生队列或后端内部适配有唯一权威状态；宿主没有镜像调度器再次认领。
- [ ] O06 以隔离工具验证一次模型工具循环，只执行实际调用一次，工具事件不触发二次动作。
- [ ] O07 以隔离模型夹具强制触发压缩，验证原生压缩记录、近期消息、历史保留及重启恢复。
- [ ] O08 上下文压缩失败不清空原上下文，不能把累计 Token 显示成窗口当前占用。
- [ ] O09 支持的撤回核对具体原生输入；已启动输入返回不可排队撤回。
- [ ] O10 全局连接设置变化不改变已接收输入的账号、模型和配置修订。
- [ ] O11 进程重启后来源事件身份、输入和结果不重复，工具副作用未知时进入核对。
- [ ] O12 原生上下文、工具、人格与数据库没有被复制成宿主中的第二套执行系统。
- [ ] O13 模型目录、鉴权测试、实际模型生成分别记录，不以目录成功代替生成成功。
- [ ] O14 循环重复工具、重复正文、空响应、上游限流按有限预算终止并报告原因，不无限自恢复。

退出条件：在隔离数据上完成普通会话、工具、压缩、原生接纳和异常恢复。真实外部模型测试需明确记录请求数与实际用量；不通过向 QQ 发送无关测试消息完成验收。

## 5 阶段 P3 现有客户端闭环

交付：会话列表、连接选择、消息/队列展示和事件恢复通过新的通用门面运行，视觉保持现有样式。

- [ ] U01 初始显示最近10条缓存，后台更新不能把旧快照覆盖新状态。
- [ ] U02 向前加载保留锚点，不跳到顶部，不出现重复和倒序消息。
- [ ] U03 空闲发送不会先进入等待队列再弹回正文。
- [ ] U04 忙碌发送在后端回执后立即显示排队项，不等待上一轮回复。
- [ ] U05 最终消息先提交、结束状态随后更新，下一输入开始不会把前一结果插到后面。
- [ ] U06 引导按钮收到提交回执立即反馈，实际已应用只按原生事件展示。
- [ ] U07 已发送未回复的输入有自己的稳定归属，不挂到前一 AI 结果。
- [ ] U08 切换会话只改变订阅，后端队列、执行和输出继续。
- [ ] U09 排队调序使用预期队列修订，过期操作不会覆盖另一端的变更。
- [ ] U10 原生撤回返回成功后才恢复草稿；不支持的按钮禁用或隐藏。
- [ ] U11 历史消息不弹入，新消息动效按 ID 只播放一次。
- [ ] U12 后端 A 离线时，其会话明确离线，后端 B 的列表和发送保持可用。
- [ ] U13 使用第二套测试后端，不修改前端分支即可展示其历史和能力。
- [ ] U14 今天、最近7天、累计用量有来源；未报告不变为0，未配置计价不虚构费用。
- [ ] U15 无等待项时不显示“队列0”；运行项按真实事件展示，与等待队列分别渲染。

退出条件：同一组交互用例至少针对完整测试后端和 OpenCode 参考后端各运行一次。渲染测试、真实浏览器、原生 WebView2 验证分开记录，不互相替代。

## 6 阶段 P4 故障注入与交付

| 编号 | 注入点 | 必须观察的结果 |
| --- | --- | --- |
| R01 | 宿主写入输入后退出 | 原记录可核对，不丢需求，不自动新建 ID |
| R02 | 后端落盘接纳后丢回执 | lookup 返回原输入，只执行一次 |
| R03 | 后端已执行外部动作后崩溃 | 进入原生核对，不重新做外部动作 |
| R04 | 最终结果提交后宿主断线 | 重连补收结果，随后才显示结束 |
| R05 | 事件重复、延迟和游标过期 | 去重或快照恢复，不错序追加 |
| R06 | 同一队列两端并发调序 | 只允许一个预期修订成功 |
| R07 | 实例 A 持续无响应 | 只隔离 A，B 仍有可用回执 |
| R08 | 实例 A 崩溃和 PID 被复用 | 不操作后来的无关进程 |
| R09 | 配置保存和新输入并发 | 每个已接纳输入只有一份冻结配置 |
| R10 | 磁盘满或写入失败 | 不返回已可靠接收，原生已接纳时保留核对线索 |
| R11 | 发送成功但渠道确认丢失 | 保留 unknown，不重复执行任务，不伪称确认发送 |
| R12 | 宿主缓存损坏 | 经后端接口重建公开展示，原生上下文不变 |
| R13 | 异常后端高频输出 | 有界背压，不丢关键接纳/结果事件，不无限增内存 |
| R14 | 手动维护有排队项的实例 | 排空/持久化策略真实执行，既不丢队列，也不因排队永远卡住 |

本地幂等模拟可以验证内部一次执行；不具备幂等或核对 API 的外部系统只能验证不会盲目重放，不能宣称全链路恰好一次。

退出条件：F、H、O、U、R 检查都有可重跑用例与结果，明确哪些是模拟、哪些是真实集成。新地基候选版仍不自动切换生产入口。

## 7 性能验收

先记录当前机器上的基线，比较相同历史样本、相同视口和相同后端夹具。指标包括宿主打开时间、尾部缓存首显、历史翻页、排队回执到可见的延迟、事件积压、空闲资源与后端故障时其他会话的延迟。

地基引入的内存、线程和磁盘写入必须有上限。持续 Token 文本可以合并，但关键边界可靠落盘。压力测试覆盖至少两套后端、多会话和长历史；不能只测一条空会话就声称整体性能优化完成。

不在没有基线时承诺固定毫秒数或百分比。性能监控本身仍按需开启，不能通过常驻高频扫描来证明低开销。

## 8 后续模块迁移准入

只有 P4 通过后才另外安排业务迁移。每个后续任务都需要明确旧数据所有者、公开导出、目标包、唯一接纳所有权、回滚方式和兼容用例。

Codex 原生后端的第一项验收应验证原线程、账号、上下文和压缩都保留，不要求改成 OpenCode 的内部数据模型。QQ 接入的第一项验收应验证它只转交和发送，不恢复自己的执行队列。研究、下载、影视与音乐的职责重排另写范围，不在地基任务中顺手改造。
