# QQ 接入与附属机器人边界

这是已确认的架构分工。`modules/qq-portal`已有转发实现；Q1-04已接入独立`modules/qq-chatbot`的原生会话、人格/成员记忆、认证QQ收发及产品CLI/模块配置，默认关闭。真实小羊账号和私人历史仍未迁入，不扩充转发模块的人格或模型循环。

## 组件分工

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| QQ协议与账号基础能力 | 认证连接、账号身份、结构化事件、发送/引用/撤回、受控附件、连接状态 | 判断闲聊或任务、人格、记忆、任务调度 |
| `qq-portal` 会话转发插件 | 白名单与任务@规则、绑定、命令、引用归属、历史补收、原生输入转交、任务结果回传 | 闲聊人格、群记忆、主动插话、表情包选择、独立模型执行 |
| `qq-chatbot` QQ聊天附属插件 | 小羊等人格、回复开关、群聊参与策略、成员身份、聊天记忆、图片理解与表情包 | 助手控制命令、任务绑定、操作转发机器人的队列、接收全局任务通知 |
| 原生会话核心／整套后端 | 输入、Inbox、执行、历史、上下文、压缩和用量 | QQ专有的人格、账号分工与群聊策略 |

“附属”表示它可选地依赖QQ接入能力，不表示它属于`qq-portal`内部的聊天模式。插件的启停、配置、数据命名空间和失败状态独立；未安装聊天插件仍可转发任务，关闭转发插件也不应停掉聊天插件。两者都不是核心启动条件。

协议实现复用为普通依赖库，不必再造第三个必装功能插件或新的宿主。QQ迁入阶段已提取`modules/qq-protocol`公共入口，任务转发使用同一实现；小羊接入时不得直接导入`qq-portal/src/*`私有文件。长期连接仍由原生应用Scope下的业务模块管理，每个账号只有一个明确的连接所有者。当前库实现同进程账号唯一连接，跨进程租约未实现；不能声称独立多进程已具备全局登录锁。

## 隔离规则

- **账号和路由**：任务机器人与聊天机器人使用各自账号和凭据。默认一个机器人账号归属一个业务插件，不让两个插件同时登录、抢同一消息或同时回复。同群中的两个账号只处理自己接收身份下的消息；不能因看到另一机器人的@或回复就接管其业务。
- **上下文和记忆**：转发插件只保存绑定、来源、去重和回执元数据。聊天插件通过公共接口使用独立原生会话；默认以“插件＋机器人账号＋私聊对象或群号”隔离。群内可共用上下文，但每条消息标明实际成员身份，不能把A的经历当成B的记忆；不同群、私聊和任务会话不串用。
- **人格和回复规则**：人格、字数、插话、只读不回、@能力及表情包属于聊天插件。任务机器人的群白名单＋成员白名单＋@任务机器人规则不能自动套用到聊天插件；聊天插件也不能改变任务入口规则。
- **权限和工具**：聊天插件不继承转发插件的命令权限、Codex绑定或操作工具。已授权的只读工具、搜索等由聊天插件的独立能力清单配置；不得借闲聊调用任务控制或绕过工具裁剪。
- **输入和通知**：聊天图片、表情包和群历史按自身策略处理；任务回执仍由转发插件发送。消息ID和引用复用协议格式，业务映射按插件和账号隔离，不共用“最近任务”或回复目标。
- **状态和故障**：QQ在线、转发插件启用、聊天插件启用是不同状态。人格、模型或记忆故障只影响聊天插件；转发故障不关闭另一账号。账号基础设施异常只影响依赖该账号的能力，不阻塞主应用或无关插件。

4. 分别验证：只启用转发、只启用聊天、同时启用不同账号，以及任一账号断线/插件停用；另测同群隔离、跨群/私聊记忆隔离、成员归属、权限不继承和独立回复开关。
