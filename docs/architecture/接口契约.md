# 整套会话后端接入契约

本规范定义宿主如何接入一整套会话后端。后端内部的存储、队列、压缩与工具实现不受宿主类型系统约束；它们的公开边界必须可查询、可关联和可恢复。规范版本为1，实际实施范围见进度记录，不以规范中的方法表冒充运行接入。

## 1 接入包与实例

后端交付一个完整包。宿主读取静态清单后完成兼容检查，按实例启动或连接它，再调用 `backend.describe` 协商能力。清单加载不执行代码，不探测模型，不要求先登录 QQ。

清单声明包 ID、版本、类型、宿主协议、运行方式及一个后端入口。配置、历史、工具、上下文等不再声明为必须独立安装的包。一个完整包可以内部使用原生程序和多个子进程，所有权由后端维护并向宿主报告。

同一包允许多个隔离实例。实例有稳定 `backend_instance_id`、专属数据目录和进程世代；删除一个连接不等于卸载后端或删除原生历史。宿主通过独占实例租约避免同一数据目录同时有两个写入者。

配套 [包清单 Schema](contracts/module-manifest.schema.json) 与 [后端描述 Schema](contracts/backend-descriptor.schema.json) 定义基础结构。示例中的能力值只用于设计和测试，不代表当前生产后端已实现。

## 2 最小接入接口

| 接口 | 输入要点 | 返回要求 |
| --- | --- | --- |
| `backend.describe` | 协议版本、实例身份 | 后端版本、所有权、必需方法、可选能力 |
| `connections.list` | 授权主体、游标 | 此主体可使用的连接；不得含密钥 |
| `conversations.list` | 授权主体、游标、页大小 | 稳定会话 ID、标题、状态与下一游标 |
| `conversations.open` | request ID、连接引用、新建或关联请求 | 精确原生会话引用；重复请求不再建第二条 |
| `history.read` | 会话引用、before/after/tail、页大小 | 稳定消息、方向游标及一致性水位 |
| `inputs.submit` | 原请求 ID、会话引用、冻结连接、内容与来源 | 持久接纳回执或明确拒绝；未知单独表示 |
| `inputs.lookup` | 原请求 ID、会话引用 | 原回执与原生状态；结果未知不能等同未接收 |
| `events.subscribe` | 持久来源游标 | 有序、可恢复、可去重的事件流 |
| `state.snapshot` | 会话或请求引用 | 带来源水位的当前状态，用于事件缺口恢复 |

宿主生命周期另外通过 `runtime.hello`、`runtime.health`、`runtime.drain`、`runtime.stop` 管理同一完整实例。外部服务模式的 stop 默认仅断开本实例，不关闭共享外部服务；托管进程模式才可停止已确认归属的进程。

最小接口的“可恢复”可以由完整后端适配层实现，不要求原生系统本来就使用同一种 API。但不允许宿主代替后端维护原生执行状态。

## 3 可选能力对应的操作

| 能力键 | 可选方法 | 约束 |
| --- | --- | --- |
| `queue_inspect` | `queue.snapshot` | 后端权威状态，包含单调修订号 |
| `queue_reorder` | `queue.reorder` | 同一会话、预期修订、稳定输入 ID，不移动已开始项 |
| `queue_withdraw` | `queue.withdraw` | 精确输入、原子判断是否尚未执行 |
| `input_adjust` | `inputs.adjust` | 精确原输入或运行，返回收到/提交/应用的区别 |
| `cancel_run` | `runs.cancel` | 区分请求取消、确认取消和结果未知；不承诺回滚 |
| `pause_run` | `runs.pause` | 只在原生安全边界应用 |
| `resume_run` | `runs.resume` | 恢复精确原运行或按原规则重新入队 |
| `context_inspect` | `context.inspect` | 公开容量、来源和摘要指标，不返回私有思维链 |
| `compact` | `context.compact` | 后端内部执行原生压缩，宿主只请求和展示 |
| `usage` | `usage.read` 与用量事件 | 标记真实/估算/未报告及各字段口径 |
| `session_export` | `conversations.export` | 公开历史与资源；不声称可无损转为其他后端原生上下文 |
| `human_interaction` | `interactions.respond` | 对精确权限或人工问题响应，不操作最新待办 |
| `connection_setup` | `connections.configure` | 后端提供自己的连接配置与原生登录流程 |
| `attachments` | 输入与历史附件引用 | 支持读取范围、内容类型和生命周期，不接受任意路径 |
| `resources` | `resources.read` | 同一后端内受授权分块读取；attachments 必须同时声明 resources |

缺少能力时统一返回 `unsupported_capability`，不得通过更危险或语义不同的操作模拟。例如：压缩不支持时不能删旧消息；排队撤回不支持时不能停止整个会话。

这些方法属于同一后端的门面。`context.compact` 的存在不代表一个可单独安装或被宿主调度的“压缩插件”。

## 4 身份与对象标识

| 对象 | 生成者 | 用途 |
| --- | --- | --- |
| `principal_id` | 宿主 | 已授权的本机或外部主体 |
| `conversation_id` | 宿主 | 稳定的应用会话引用 |
| `backend_instance_id` | 宿主 | 完整后端实例 |
| `native_conversation_id` | 后端 | 原生会话/线程身份，宿主不解释其格式 |
| `request_id` | 发起端或宿主 | 一次输入或控制请求的幂等身份 |
| `native_input_id` | 后端 | 原生输入或 Inbox 项 |
| `native_run_id` | 后端 | 真实执行轮次；排队阶段允许为空 |
| `external_message_ref` | 渠道适配 | 原始来源及引用关系，不混入正文提示词 |
| `event_id` | 后端 | 来源事件的持久去重身份，与事件 Schema 同名 |
| `stream_id` 与 `sequence` | 后端 | 来源事件日志身份与递增序号 |
| `runtime_generation` | 宿主 | 当前实例进程世代，用于拒绝旧进程的状态变更 |

世代与事件流身份不同：后端进程重启改变进程世代，但保留持久事件日志的 `stream_id` 和序号。旧事件按原身份重放可用于补收，不因为进程变化重做执行。日志被重建时必须变更 `stream_id` 并要求从一致快照恢复。

每个后端请求携带宿主核实的身份作用域。模型生成的主体号、网页文字或消息前缀不能改变权限。不同群、私聊和后端实例的记忆范围由整套后端维护，宿主只传递正确身份与可见性。

## 5 提交与接纳示例

宿主将本机输入转交到已经选定的完整后端：

```json
{
  "jsonrpc": "2.0",
  "id": "rpc-submit-01",
  "method": "inputs.submit",
  "params": {
    "protocol_version": 1,
    "request_id": "input-01",
    "principal_id": "local-user-01",
    "conversation_ref": {
      "conversation_id": "conversation-01",
      "backend_instance_id": "backend-01",
      "native_conversation_id": "native-session-01"
    },
    "connection_ref": {"id": "connection-01", "revision": "rev-7"},
    "runtime_generation": "boot-03",
    "input": {
      "parts": [{"type": "text", "text": "整理一下现有资料"}],
      "attachments": []
    },
    "source": {"channel": "desktop", "external_message_ref": null}
  }
}
```

后端持久接收但尚未执行时返回：

```json
{
  "jsonrpc": "2.0",
  "id": "rpc-submit-01",
  "result": {
    "request_id": "input-01",
    "accepted": true,
    "durable": true,
    "native_input_id": "native-input-01",
    "native_run_id": null,
    "execution_state": "queued",
    "receipt_id": "receipt-01",
    "queue_revision": "queue-9"
  }
}
```

RPC 调用的 `id` 是一次传输身份，`request_id` 是同一输入跨重试的持久身份。重连可以产生新的 RPC id，但不能改变原 request ID 来绕开结果未知。

持久接纳回执返回后，宿主才能显示“已排队”。只有后端实际发出 `input.applied` 或可核验的同义原生事件，才显示执行器已经接纳应用；不能以第一次 AI 回复来倒推已读。

## 6 事件契约

公共事件信封见 [事件 Schema](contracts/backend-event.schema.json)。公开部分采用有界 JSON；大型正文与附件可以返回受控引用。

推荐事件类型如下，允许后端发布有命名空间的附加类型，宿主对未知可选类型只保留记录：

| 类型 | 含义 |
| --- | --- |
| `input.accepted` | 后端已持久接收输入 |
| `input.applied` | 输入已实际进入执行轮次或按原生安全边界应用 |
| `queue.changed` | 权威队列修订或新快照可读 |
| `run.started` | 精确原生运行已开始 |
| `message.upsert` | 一个稳定消息及其内容版本更新 |
| `message.committed` | 公开消息内容已定稿且可通过历史读取 |
| `run.waiting` | 等待人工、资源或原生后端处置 |
| `run.completed` | 最终结果引用已提交，执行正常结束 |
| `run.failed` | 执行已明确失败，包含可公开的原因码 |
| `run.cancelled` | 原生取消结果已确认 |
| `context.compacted` | 后端确认完成压缩，不包含私有压缩内容 |
| `usage.reported` | 某次生成的用量口径和数据 |
| `backend.health_changed` | 实例健康变化，不直接修改任务结果 |

同一来源中，最终 `message.committed` 必须先于该运行的 `run.completed`；下一运行的开始事件不能使客户端把前一个结果排到后面。宿主先落地事件和通知待发项，再更新前端。通知是否已发送不影响后端继续执行。

V1 stdio 的 events.subscribe 回执包含有界补收 items、不透明 cursor、has_more；每页最多100个来源事件。has_more 时用返回游标继续补收，同时从该水位之后接收 backend.event 通知。通知和补收可能交叠，消费者按来源身份去重；仅持久写入后才能确认游标，后端不能因通知写出就删除来源记录。游标绑定已授权主体与实例来源流，跨作用域或保留范围失效返回 cursor_expired。订阅变更只改变公开事件流，不暂停后端执行。

V1 的 `message.upsert` 是完整公开版本替换，不接受文本 delta。消息包含不透明 id、正整数 revision、会话内唯一且不变的正整数 order、role、phase、可空 request_id/native_input_id/native_run_id；事件内的归属字段必须与外层一致。历史返回相同形状。仅较新修订替换原消息，重放不拼接文本；order 不因编辑或上下文压缩改变。订阅消费者的游标在持久写入后推进。

## 7 快照与事件的衔接

`state.snapshot` 返回 `stream_id`、`through_sequence`、对应会话状态和当前后端队列修订。它必须与返回的事件水位一致；宿主不能把多个时间点的独立查询拼成一个假原子快照。

事件游标失效时，宿主获取快照，原子替换对应实例的可重建投影，再从该水位之后订阅。按稳定 request、消息和事件 ID 对账，已收到的结果不重复通知。

并发修改带 `expected_revision`，后端成功后返回新修订。旧修订冲突返回真实最新状态的查询引用，宿主不得自动覆盖用户其他端已完成的修改。

## 8 历史接口

接口支持 `tail`、`before` 和 `after` 三种互斥读取方向。至少提供稳定消息 ID、稳定顺序、消息修订、内容片段、运行和输入归属以及分页游标。

游标不是数组下标或单纯墙钟时间。源端加入新消息、压缩原生上下文或更新流式消息，不得让前翻丢项、重复或错序。后端内部数据格式变化时，由后端适配层维持这个公共接口。

压缩只影响有效模型上下文，不等同删除公开历史。若某后端原生确实不保留完整历史，完整后端包内补充自己的公开档案，而不是让宿主凭零散输出猜造缺失记录。

附件通过 `resource_ref` 提供受限访问，说明 MIME、字节数和可读取期限。资源失效时原消息保留“附件不可用”，不伪装模型已看过或在后台无限重抓。

消息正文在 text 与 resource_ref 中二选一，text 最长262144字符，整帧仍受4 MiB字节限制。attachments 可含至多32个资源引用。资源引用包含 id、backend_instance_id、conversation_id、mime_type、size_bytes、expires_at（可空）；不是本机路径或可自行访问的 URL。

resources.read 的参数为 principal_id、conversation_ref、resource_ref、offset、limit。offset 是非负字节偏移，limit 为1至262144；返回 resource_ref、offset、data_base64、eof。实际解码块最多256 KiB，不得越过 size_bytes，只有到达已声明大小时 eof=true。空块仅允许在文件末尾。调用者校验返回引用、偏移与请求一致、实际大小不超过请求 limit；后端校验已授权主体、资源的实例/会话归属及有效期。跨域返回 permission_denied，过期返回 resource_unavailable，不触发重新下载。纯文本后端可不声明 resources，使用有界 text 即可；不新增独立资源插件。

## 9 上下文 压缩和工具

后端描述固定声明 `context`、`history`、`queue`、`tools` 和 `compaction` 的所有者为 `backend`。这是所有权约束，不规定后端内部由几个组件实现。

`context.inspect` 可以返回原生引用、当前使用量、上限、指标来源、最近压缩时间及公开状态。无法读取时返回 unknown；累计输入 Token 不能替代当前窗口占用。

`context.compact` 只表达用户向完整后端发起压缩请求。后端选择何时可压缩、采用哪种原生策略和如何保存自身状态。操作绑定原会话和预期修订，宿主不向其传入另一套后端的压缩摘要充当原生状态。

工具调用由整套后端执行。后端可以通过未来模块公共能力调用宿主工具，也可以按自身已有权限运行原生工具。工具权限没有因为接入整套后端而自动扩大；来源材料不构成操作授权。宿主只记录公开工具活动和明确回执，不将收到的工具事件再执行一次。

## 10 连接配置与账号

后端提供连接列表，宿主可以展示为统一选项。配置字段和登录动作可以由后端声明或提供隔离视图；宿主不硬编码特定上游模型 ID、账号目录和登录过程。

连接引用包括 ID 和配置修订。输入接纳后冻结其使用的连接；改变默认账号只影响之后接收的输入。登录到另一账号不应悄悄继续原账号未完成任务。

后端没有收到明确的有效鉴权时拒绝请求，不自动借用另一账号或改投另一个模型。探测连接、读取模型列表与实际生成分别记录，不能用端口可达冒充会话能力正常。

## 11 错误语义

公共错误至少返回 `code`、可读 `message`、`retry_policy` 和相关 request ID。原始凭据、密钥和私有提示不进入错误正文。

| 错误码 | 宿主处理 |
| --- | --- |
| `backend_unavailable` | 只标记目标后端或连接不可用 |
| `unsupported_capability` | 隐藏或禁用对应操作，保留其他功能 |
| `permission_denied` | 保留原需求并提示权限，不能换主体绕过 |
| `revision_conflict` | 重新读取权威快照，由明确操作再提交 |
| `idempotency_conflict` | 停止重试，提示同 ID 内容不一致 |
| `request_unknown` | 后端还不能确认原输入，继续核对，不表示未执行 |
| `request_absent_confirmed` | 后端在明确一致性范围内确认未接纳，可以按原 ID 转交 |
| `external_result_unknown` | 后端需核对副作用，宿主不重放 |
| `cursor_expired` | 按一致快照恢复 |
| `interaction_required` | 展示精确待处理事项和后端操作入口 |
| `backpressure` | 显示未发送或当前容量限制，不能伪造执行中 |

重试不能由通用 HTTP 中间件无条件执行。只读查询可以有限重试；提交、取消、工具动作和通知发送按它们的幂等与核对能力处理。

## 12 生命周期与版本

宿主从静态清单读取声明，再在 `runtime.hello` 中验证本实例、协议、数据版本和进程世代。后端宣布 ready 前不接收需要原生能力的输入，但不阻塞宿主页面。

`runtime.drain` 返回真实在途数量、排队是否已持久保存、是否支持安全停止以及具体阻塞。只有相关实例被暂停接纳；不能把其他后端的活跃任务作为维护本实例的阻塞条件。

后端无法优雅停止时，宿主保留其状态和原因，不伪称已卸载。异常进程退出触发该实例恢复核对，不能将 PID 复用后的其他程序视作旧进程处理。

宿主协议主版本不兼容时拒绝加载。可选新增能力通过次版本与声明协商；缺少可选能力仍能完成基础会话。原生 SDK 升级先通过适配器契约测试再发布新包，不让上游类型变化直接传播到前端。

V1 的已定义字段严格校验。未来可选声明放入后端描述的 `extensions` 或包清单的 `contributions` 命名空间，老宿主可以忽略未知命名空间并保留基础接入。不能把一个新必需功能藏进未知可选字段，或让宿主猜测其执行方式。

## 13 契约测试标准

接入测试同时验证结构和行为。JSON Schema 校验只能证明形状符合设计，不能证明幂等、真正持久化、实际接纳或原生恢复已完成。

后端完成声明的所有必需行为后，才进入可用目录。每个可选能力分别有通过记录。假后端负责覆盖边界和故障，OpenCode 参考后端还需针对锁定包运行隔离集成测试；真实上游模型和原生窗口测试单独记录，不互相替代。
