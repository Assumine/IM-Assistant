# 原生接口与助手补充边界

当前基座是完整 OpenCode 应用。原生会话、历史、数据库和客户端之间沿用锁定版本的真实 API、事件、类型与错误；不强制外包一层原计划的 Python SDK/JSON-RPC。

## 接口来源

| 边界 | 规则 |
| --- | --- |
| 原生前端 → 原生服务 | 使用上游客户端、订阅与交互状态，不另定义平行消息协议 |
| 会话 → 原生数据库 | 使用上游存储、事务、索引和迁移，不由QQ或助手脚本直接改表 |
| QQ → 应用入口 | 身份、授权、会话/输入/引用/附件映射明确，可靠转交到同一输入能力 |
| 应用 → Codex原生执行器 | 保留原生ID与上下文/压缩/执行状态；适配可行性须验证，不伪装成模型请求 |
| 应用 → 业务能力 | 优先原生插件/RPC，服务只提供声明能力及自身数据，不接管全局发送 |
| 受控附件与业务文件 | 用受限资源引用，不暴露任意路径、通用shell或项目文件操作 |

助手新增边界至少保留授权主体、来源消息、目标会话、稳定输入身份及精确操作目标；区分接收、排队、执行和通知，未知结果先核对，不自行改ID重发。这些是验收语义，不是要求替换上游公开类型。

QQ绑定、通知发送、模块配置等扩展数据由所属能力拥有。原生数据只经原生访问路径；业务扩展不能直接补写一条“已完成”消息，不能凭通知成功反推任务完成。

文件工具裁剪必须覆盖UI、模型工具注册、直接API、命令和插件入口。权限不能由模型输出、网页文本或消息标记改变。内部数据库/附件文件服务不是对模型开放的项目文件工具。

## 历史参考的地位

本目录 contracts/ 的三份Schema与 examples/，以及根 sdk/ 和测试夹具，是旧 Python 宿主探索阶段的参考产物。保留它们用于反例、幂等、事件顺序和隔离经验，不声称是当前OpenCode的原生接口，也不要求每个OpenCode调用绕过它们。

原规范全文见 [旧接口归档](../archive/python-host-plan/接口契约.md.txt)。R0锁定上游后逐项核对能力，实际需要的助手补充协议随对应任务记录，不提前把所有上游接口重新包装一遍。
