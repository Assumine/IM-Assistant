# R5：隔离发布验收和逐会话切换

此阶段验收完整 OpenCode 基座及助手补丁。业务模块迁入、安装包发布、真实账号启用与生产入口切换是后续动作，不能用隔离测试通过代替。旧客户端源码、资料和数据库保留本地。

## 状态所有者

- 普通会话的接纳、Inbox、历史、上下文及压缩仍由原生 OpenCode 持有。
- Codex 线程、原生队列、账号及压缩由 Codex App Server 持有，整套后端通过公共接口接入；不导入成普通 Session 再执行。
- QQ 只保留输入转发、引用归属及独立投递回执。通知失败不重发任务；结果未知的发送不自动重试。
- 小羊是另一个可选能力插件，尚未迁入；不能借 QQ 转发插件共享其账号、人格或记忆。

## 验收入口

使用锁定的 Bun/Node/Codex 版本和隔离 HOME：

```text
.venv/Scripts/python.exe -X utf8 tools/validate_design.py
.venv/Scripts/python.exe -X utf8 tools/run_runtime_checks.py --task R5-01
```

入口先检查修改过的浏览器 keeper，再串行采样性能，随后执行原生核心、客户端、桌面存储、历史/发送状态、文件能力裁剪、真实 HTTP/SQLite 演练、Codex App Server、多账号 loopback OneBot 和构建。模拟的只有模型输出和 loopback 传输对端，不模拟 Session 或排队状态机。必需项失败、跳过或零用例均不能通过。

结果见 `tests/rebase/release-evidence.json`；详细日志、合成会话切换清单、性能原始数据留在不提交的 `.reports/native/`。R0–R4 原始证据保持各自的源码版本，不能改写成此次版本已经重新通过。R5 入口另行运行当前源码。

## 可比较的性能

R4 未换肤的生产浏览器基线已固定在 `upstream/theme-baseline.json`，仍按同一 40 条消息、三个串行样本比较导航至标题/尾消息/输入框可见的时间。

R5 清理的是测试协议和探针类型，不改生产实现。服务启动、10 条历史分页、首 token 前接纳回执及空闲 CPU/内存采用六个串行样本，并先验证生产代码与 `ab68bc75348da9e3e4593766345f5fb07b6291b6` 相同。这里的“参考/候选”运行同一份经过身份核对的生产代码，体现局部波动，不能宣称 R5 带来性能提升。生产实现发生变化时，该身份条件必须失败，重新建立独立参考版本，不能继续套用。

启动指冷配置的原生服务就绪，不是操作系统冷启动或安装包首屏；历史分页指真实 HTTP/SQLite 返回时间，渲染由另一项生产浏览器基准观察；空闲计数只覆盖测试拥有的服务进程和三秒窗口，不代表整个桌面所有子进程。保留原始值，不设机器相关的速度门槛。监测仅在测试期间采样，不增加产品后台轮询。

## 切换记录

正式切换前，每个会话单独建立记录，存本地，不上传真实 ID、正文或账号：

| 字段 | 内容 |
| --- | --- |
| 原生身份 | 后端类型、原 profile、原 thread/session ID；不把 Codex ID 转成 Session ID |
| 原接纳方 | 已接收消息 ID、运行/等待/排队状态、最后确认的回执和历史边界 |
| 切换前核对 | 原任务完成或人工核对结果；Inbox 清空；未知副作用逐项确认 |
| 只读资料 | 导出摘要/校验和、受控附件、格式版本；原库保留并验证可恢复 |
| 目标位置 | 新隔离 profile、新接纳入口；记录原生导入结果和冲突 |
| 生效边界 | 从哪条**新**消息开始由目标接纳；已接纳消息不重新投递 |
| 回退边界 | 从哪条**新**消息恢复原入口；目标已接纳内容仍归目标核对 |
| 确认事实 | 操作时间、结果、回退原因；不能把通知已发送当作任务完成 |

不得直接合并或替换两套 SQLite 文件，不在运行中的库上覆盖文件。原生历史导出不包括可执行 Inbox，也不替代旧客户端的真实格式转换器。旧客户端的实际数据转换尚未实现，不得直接读库重放旧任务。

## 隔离演练

1. 源 profile 接收 A，B 留在源 Inbox；源完成两项并清空 Inbox。
2. 使用原生 export/import 将已落定历史导入新 profile，保留原生 ID。重复导入必须冲突，不能覆盖；导入和浏览不得触发模型执行。
3. 新输入 C 只进入目标。决定回退后，新输入 D 只进入源；不复制 C 回源，不重复运行 A/B。
4. 两端重启，核对各自历史顺序与输入 ID；共四次模型请求，没有因导入或重启额外执行。
5. 另一次测试强制结束自己拥有的服务进程，核对已完成输入不重放、持久 Inbox 不丢失、同 ID 的丢回执重试仍读取原始输入。原生重建的投递回执时间不等同于首次接纳时间，不能拿整个 JSON 字节相等替代身份和历史核对。

合成演练清单在 `.reports/native/r5-migration-manifest.json`，仅用于验证协议，不是生产路由表。没有创建另一套可执行队列。

## 故障与回退限制

原生崩溃恢复对未完成推理是至少一次恢复，不保证任意外部副作用恰好一次。文件/shell/MCP 等项目能力已在助手模式裁剪；以后业务模块接入下载、支付或修改服务时，仍须使用其原生幂等键和结果核对，不能据此测试宣称可以盲目重试。

QQ 断连和结果未知发送目前保持显式不可用/待核对，避免第二次发出同一副作用；自动重连、远端未知发送核销和普通 Session 无正文失败通知仍是后续缺口。真实平台限流及验证码不由 loopback 验收代替。

正式入口、自启、真实账号、旧记录删除均未切换。回退是更改后续接纳入口和保留事实，不表示撤销已经发生的操作。
