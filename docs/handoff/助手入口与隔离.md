# 助手入口与原生存储隔离

R1-01 在原 OpenCode Electron/CLI 启动链上增加个人助手配置。产品代码位于 `opencode/packages/im-assistant/`，包名 `@im-assistant/profile`。这是一层产品身份与启动配置，未增加会话宿主、数据库代理、消息缓存控制器或执行循环。

## 开发入口

先按 [原生基线运行](原生基线运行.md) 安装隔离工具链与依赖，再从新仓库根目录执行：

```sh
python tools/native_baseline.py --cwd packages/desktop --label assistant-build -- x electron-vite build
.\runtime\tools\bun-1.4.4\bun-windows-x64-baseline\bun.exe --cwd opencode/packages/im-assistant run desktop
```

第一个命令是构建自动化，第二个是助手的原生桌面开发入口。入口仅给自身及子进程增加 Bun 路径，免除全局安装要求。CLI 诊断也有同一产品配置入口：

```sh
.\runtime\tools\bun-1.4.4\bun-windows-x64-baseline\bun.exe --cwd opencode/packages/im-assistant run cli debug paths
```

这仍是开发构建；尚未制作、签名、安装或设置生产自启。UI 仍为原生 OpenCode，产品换肤在 R4-02；R1-02 已完成项目树及文件工具的裁剪，见[会话模式能力边界](会话模式能力边界.md)。不要用上游打包脚本下载 dev CLI 来替代锁定源码。

## 身份与数据所有权

助手身份固定为 `tools.assumine.im-assistant`，名称 `IM-Assistant`。Windows 默认根目录为 `%APPDATA%/tools.assumine.im-assistant`；可在启动前显式设置绝对路径 `IM_ASSISTANT_DATA_ROOT` 使用独立/便携目录。根路径与身份重开后保持稳定，不读取旧助手数据，不自动迁移既有 OpenCode 登录态。

| 路径 | 所有者与用途 |
| --- | --- |
| desktop/ | 原生桌面设置、草稿/状态 SQLite 与窗口信息 |
| session/ | Chromium 会话、浏览器缓存，与原版桌面分开 |
| native/data/opencode/ | 原生数据库及其内部数据，由原生服务写入 |
| native/config/opencode/ | 原生配置、凭据关联配置、专用服务设置 |
| native/state/opencode/service-im-assistant.json | 原生服务注册信息，含私密本地鉴权，不提交或公开输出 |
| native/cache/、tmp/ | 应用自己的缓存和临时目录 |
| session-location/ | 原生 Location 的管理位置，启动直接创建草稿进入输入框 |

本阶段没有助手会话表或第二套队列。消息接收、Inbox、历史、执行、压缩和原生数据库的所有者不变。未来扩展元数据按模块自己的命名空间/公共接口接入，不能直接补写原生会话私表。

## 启动与连接约束

- 模式开关为 `IM_ASSISTANT_PROFILE=personal`，由开发入口设置；未启用时保持原版模式。
- 助手使用独立服务注册文件，通过原生 Service.ensure/discover/stop 发现与管理同一原生服务。默认仅监听 127.0.0.1:28716；已有专用服务设置不被首次默认值覆盖。
- 清除继承的 OpenCode 内联配置/外部配置文件/服务密码及旧测试目录指向，并覆盖数据库、XDG 和内部临时路径，避免旧启动器把新应用导向旧库。
- 操作系统 HOME 不改动。原生服务上下文的 home 和默认工作位置设为管理位置；它不是用户真实工作区。服务层新增通用 project.discover 开关，助手关闭项目发现，原版保持默认。Core 不依赖助手业务包。
- 无 QQ、网关、模型登录也能进入输入框和设置。业务连接将在对应阶段接入；开发验证没有调用真实用户模型。
- 不抢占原版 opencode:// 默认协议，不更改正式自启。助手自己的深链、OAuth 回跳与打包更新归后续适配/发布验收，本阶段不声称已完成。

## 验收

```sh
python tools/run_runtime_checks.py --task R1-01
python tools/run_runtime_checks.py --task R0-01
python tools/validate_design.py
```

R1 入口包含实际产品进程和 HTTP 验证：无全局 Bun 环境启动，直接进入输入框；同时运行另一个合成原版配置；会话/队列互不串用；关闭桌面并停止专用服务后重开，原生会话、Inbox 与服务凭据保留；管理位置不关联父 Git 仓库，旧库及旧测试目录指向不生效。另跑上游29项 Project 回归、3项配置契约重复10次、原版完整 lint/36个工作区类型检查和桌面构建。

Project 回归的临时根必须放到 Git 仓库外；上游测试本来会向上发现标记，放到本仓库的临时目录会污染其“无标记目录”前提。助手模式另用真实服务测试验证即便便携目录位于仓库内也不发现父项目。

上游原始清单保留不变，`upstream/patches.json` 登记当前产品改动及最终 SHA256。校验器同时检查原始文件与已声明补丁，拒绝把缓存、日志或数据库列为产品源码。未登记的修改不会通过来源校验。

维护补丁台账时保留既有条目，累计比较原始清单与当前源码；不能只用当前未暂存的 Git diff 覆盖整份台账，否则已经提交或暂存的产品补丁会丢失。
