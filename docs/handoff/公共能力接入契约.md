# 公共能力接入与运行边界

可信ApplicationModule可通过可选tools字段提供原生AI业务工具。应用Scope添加模块名前缀，仅active时可见，执行检查原生Permission，停止后旧快照也不能继续调用。Location/project工具变换不能自行加入受管清单，通用execute、文件、shell与任意MCP工具仍保持原裁剪。注册失败立即释放本模块资源，不阻塞核心会话。

这是通用框架入口，核心不识别研究身份、分类或路径字段。研究身份和MCP入口由modules/research持有，原生与MCP共用同一业务契约，不另建模型循环、会话库或任务队列。

本契约对应R4-01。应用仍是锁定的完整OpenCode基座，业务放`modules/<module-id>/`。公共能力只补原生应用资源的装配、运行状态、系统通知和按需快照；不建立外层宿主、第二套会话库或执行队列。

## 状态所有者和入口

| 内容 | 原生所有者 | 本次接入位置 |
| --- | --- | --- |
| 应用资源及关闭顺序 | 原生Server/Application Scope | `@opencode/plugin/promise/application`的ApplicationModule与可信延迟Loader |
| 普通AI会话、Inbox和执行 | 原生Session/Inbox/Runner/SQLite | 继续使用原生客户端，不受本接口接管 |
| 整套Codex后端 | 原生ConversationBackend扩展＋codex-native | 保留原有后端设置/线程/上下文/压缩，不复制成影子Session |
| 模块私有数据 | 原生插件KV命名空间 | open(context).storage，仅访问自身范围 |
| 系统通知 | 原生KV中的独立通知/阅读/解决事实 | context.capability.notify/resolve |
| 元数据读取与停用 | 原生动态RPC | client.rpc(Capability.Api) |
| 声明式配置 | 各模块自有配置文件与校验器 | 可信Loader.settings＋原生Capability settings/configure RPC及Configure界面 |
| 界面 | 原生GUI插件注册 | 设置中的Application modules、Module notifications；命令菜单和Home入口 |

`packages/im-assistant/src/capabilities.ts`是产品组合位置。它只列出已编译可信模块并延迟读取配置；HTTP请求、项目配置和序列化设置不能贡献可执行代码。依赖库、Bun/Node和协议驱动不是功能模块。Codex已有整套后端扩展位置，继续沿用；不为凑统一列表另造它的连接或状态所有者。

## 装配与关闭

ApplicationModule使用稳定的小写id和可选title，open同步返回资源。异步配置用ApplicationModuleLoader.load(signal)，返回undefined表示关闭；配置异常只让该项failed，不能挡应用初始化。异步连接由模块资源自己管理，不能让open同步执行长时间阻塞工作。

每项拥有原生子Scope。load未完成就停用时，信号被取消，迟到结果不得打开模块。stop只关闭本项资源，close先结束入口和已开始的转交，再释放原生客户端/数据库；重复stop不重复close。停用后的storage、report、notify、resolve均拒绝继续写入。

运行状态为loading、active、disabled、failed、stopped。active仅代表资源打开；是否已连接由独立health（starting/ready/degraded/unavailable）说明，不能把配置开关当在线。停止后清除health和指标支持，避免出现“已停止/就绪”矛盾。

界面的Stop service只影响本次服务运行，不改账号开关、不删除绑定、不提供隐式重启。QQ账号配置enable/disable仍在下次服务启动生效；CLI status仍为期望配置，而公共运行目录才是实际资源状态。某个QQ账号异常时，由qq-portal聚合自己的连接健康，不把账号/白名单/引用规则搬入核心。

## 模块自有配置

Q1-04增加ApplicationModuleSettings。可信模块或Loader可提供read(signal)和write({revision,text},signal)，通过通用Capability.Api.settings/configure使用。原生框架只提供有界文本、版本冲突和失败反馈，不识别QQ账号、人格或其他业务字段，也不从请求加载可执行模块。

提供方负责校验、去除原始凭据、原子保存和版本核对；write返回undefined表示版本冲突，不能覆盖已变化的数据。普通异常只回报通用失败，不回传内部异常或凭据。没有提供设置的模块不展示Configure入口。配置能力独立于当前连接资源，因此服务关闭或失败时仍可编辑合法的下次启动配置；服务的当前state/health保持实际值。

原生GUI按需加载文档，明确提示下次启动生效，保存失败保留编辑内容并提示核对/重新读取，没有后台配置轮询或隐式服务重启。聊天模块对人格/模型变化要求同次保存显式增加contextGeneration；旧历史及平台来源去重保留。此业务校验由模块持有，不写入核心。

## 通知、已读和待人工处理

模块通过自身context发布通知：id、title、可选message、severity和requiresAction。moduleID由原生注册上下文决定，模块不能指定他人的通知命名空间。字段有长度/格式限制；不得放令牌、密码、完整异常堆栈或私人上下文。

同一模块同一id、同一内容重复发布是幂等操作；内容冲突拒绝。新事件必须使用新id，不能用同一个已解决事件反复冒充未读。原通知不可变：原生KV分别保存notice、read、resolved三个事实，同一数据库持久化，无第二套通知数据库或任务状态。

- 打开全文预览才标记已读。未读标记与未读数量随之清除。
- 已读不等于问题解决。requiresAction且未resolve的通知仍计入Needs action。
- 只有模块自身显式resolve才解决人工事项；GUI阅读接口不能替模块确认。
- 模块停止或下次未装配时，历史通知仍可读。重启不能因此重做AI任务、重发外部消息或重新打开连接。
- 按创建时间倒序、稳定id处理同一时间的分页边界；支持all/unread/attention筛选。原生SQL仅读取自己的通知键范围，不枚举其他插件数据。

本轮公共通知页提供独立计数和预览，不声称已经替换所有旧业务通知或完成全局通知铃铛。QQ任务首轮/最终回执继续沿原来的原生输入归属和持久发送回执，不改成系统通知调度。

## 按需监控

模块资源可以提供metrics(signal)，返回最多64个有限数值：id、label、value、unit。单位支持percent、bytes、milliseconds、count；不提供回调时明确unsupported，不伪造零占用。提供方必须遵守取消信号，停止自身采集。

原生服务只响应显式读取；相同模块并发读取合并为一次，快照至多每秒更新一次。模块停止会取消采集。没有全局定时器、全进程扫描或QQ登录前提。

GUI仅在选中模块的监控面板存在、连接可用且文档可见时约每秒读取。关闭监控、离开设置、断开连接、隐藏窗口时停止定时器并取消在途读取。恢复可见后按需继续。元数据变更使用原生RPC changed事件，不后台轮询状态。

本轮验证的是可用的公共指标入口、生命周期与可见性规则，真实硬件/进程采集器尚未迁入。后续设备或性能模块接入回调即可，不在核心加具体设备分支。

## 后续接手

S1-03新增通用只读模块文档：资源可返回`view({locale,signal})`，由`Capability.Api.view`按需读取，最多30项、每项最多16个有界文本字段。标题、状态、字段和技术记录由模块提供；框架只渲染纯文本，不接收HTML、事件处理器或执行控制。未提供、停用及读取失败分别返回unsupported/unavailable/failed，不伪造空成功。

模块通过`context.capability.invalidate()`发出定向`viewChanged {id}`事件，刷新本模块已打开的视图，不让全局模块目录反复重载。原生RPC事件的业务数据在`event.data`中，不能与事件自身的id混用。GUI在模块卡片内部展开，不新建页面或任务状态机；保留刷新期间的旧快照，取消或隐藏后拒绝迟到响应，关闭面板即解除监听，不轮询。停止模块取消视图和采集资源，清除view支持。代码及长证据只在默认收起的有界技术记录内展示。

研究配置、身份、原始输入归属、评分和采集仍归`modules/research`；核心没有研究专用字段。产品装配中QQ转发、小羊、研究共三项业务模块，全部默认关闭；协议/解释器/MCP等依赖不计作业务模块。当前研究产品验收使用`python tools/run_runtime_checks.py --task S1-03`，QQ历史证据保持其原始源码，不重写为当前结果。

小羊保持独立qq-chatbot可选插件；人格、记忆、图片、表情及工具权限不进入qq-portal。Q1-04已接产品可信Loader、独立CLI和模块设置，默认关闭；真实账号、私人历史和生产切换仍未执行。市场安装、其他业务和自动重连另按后续任务完成。

当前配置接口及产品联合验收运行`python tools/run_runtime_checks.py --task Q1-04`；R4-01原证据保持原源码版本。验收执行原生Scope/RPC/SQLite/Runner、真实产品入口回环、GUI和重复运行，不读取旧QQ/Codex证据冒充当前代码通过。真实账号、安装包及其他OS不包含在该隔离验收内。

## 有界声明式操作（W1-01）

在 S1-03 只读文档基础上，模块资源可另外提供 `invoke`；原生 `Capability.Api.invoke` 仅调用当前激活的可信资源，输入包括模块/操作/请求标识、可选目标、受长度限制的 JSON 文本及语言。调用受模块生命周期及请求取消约束；停止会撤销处理器，不允许旧按钮调用已停用资源。核心只理解通用契约，不识别链接、下载字段或具体业务动作，也不开放通用 shell、任意文件或动态代码。

`view` 可声明最多 8 项根操作、每项最多 8 个文本字段、每条记录最多 6 项操作及 0–100 的实际进度。界面只渲染原生表单和纯文本；字段不能注入 HTML/回调。模块负责校验、持久受理、幂等和最终核对。结果是 `applied`、`rejected` 或 `uncertain`，不能把连接失败当作“没有执行”。未知结果保留同一请求标识和草稿，核对后才能显式开始新操作。

业务可通过 `refreshAfterMs` 请求 1–60 秒的可见视图刷新；缺省仍是事件驱动。只有当前展开且文档可见时采样，关闭/隐藏取消在途读取、定时器和迟到响应；没有全局轮询。稳定记录/操作标识保持输入、焦点和展开状态，刷新不能重建整个表单。

产品组合新增 `downloads` 后共有四项可选业务模块，仍全部默认关闭。aria2 是下载模块自有的传输依赖，不属于 AI 会话队列。实际切换入口与业务验收分别记录；不会导入旧私有下载或自动重放任务。
