# 公共能力接入与运行边界

本契约对应R4-01。应用仍是锁定的完整OpenCode基座，业务放`modules/<module-id>/`。公共能力只补原生应用资源的装配、运行状态、系统通知和按需快照；不建立外层宿主、第二套会话库或执行队列。

## 状态所有者和入口

| 内容 | 原生所有者 | 本次接入位置 |
| --- | --- | --- |
| 应用资源及关闭顺序 | 原生Server/Application Scope | `@opencode/plugin/promise/application`的ApplicationModule与可信延迟Loader |
| 普通AI会话、Inbox和执行 | 原生Session/Inbox/Runner/SQLite | 继续使用原生客户端，不受本接口接管 |
| 整套Codex后端 | 原生ConversationBackend扩展＋codex-native | 保留原有后端设置/线程/上下文/压缩，不复制成影子Session |
| 模块私有数据 | 原生插件KV命名空间 | open(context).storage，仅访问自身范围 |
| 系统通知 | 原生KV中的独立通知/阅读/解决事实 | context.capability.notify/resolve |
| 元数据读取与停用 | 原生动态RPC | client.rpc(Capability.Api) |
| 界面 | 原生GUI插件注册 | 设置中的Application modules、Module notifications；命令菜单和Home入口 |

`packages/im-assistant/src/capabilities.ts`是产品组合位置。它只列出已编译可信模块并延迟读取配置；HTTP请求、项目配置和序列化设置不能贡献可执行代码。依赖库、Bun/Node和协议驱动不是功能模块。Codex已有整套后端扩展位置，继续沿用；不为凑统一列表另造它的连接或状态所有者。

## 装配与关闭

ApplicationModule使用稳定的小写id和可选title，open同步返回资源。异步配置用ApplicationModuleLoader.load(signal)，返回undefined表示关闭；配置异常只让该项failed，不能挡应用初始化。异步连接由模块资源自己管理，不能让open同步执行长时间阻塞工作。

每项拥有原生子Scope。load未完成就停用时，信号被取消，迟到结果不得打开模块。stop只关闭本项资源，close先结束入口和已开始的转交，再释放原生客户端/数据库；重复stop不重复close。停用后的storage、report、notify、resolve均拒绝继续写入。

运行状态为loading、active、disabled、failed、stopped。active仅代表资源打开；是否已连接由独立health（starting/ready/degraded/unavailable）说明，不能把配置开关当在线。停止后清除health和指标支持，避免出现“已停止/就绪”矛盾。

界面的Stop service只影响本次服务运行，不改账号开关、不删除绑定、不提供隐式重启。QQ账号配置enable/disable仍在下次服务启动生效；CLI status仍为期望配置，而公共运行目录才是实际资源状态。某个QQ账号异常时，由qq-portal聚合自己的连接健康，不把账号/白名单/引用规则搬入核心。

## 通知、已读和待人工处理

模块通过自身context发布通知：id、title、可选message、severity和requiresAction。moduleID由原生注册上下文决定，模块不能指定他人的通知命名空间。字段有长度/格式限制；不得放令牌、密码、完整异常堆栈或私人上下文。

同一模块同一id、同一内容重复发布是幂等操作；内容冲突拒绝。新事件必须使用新id，不能用同一个已解决事件反复冒充未读。原通知不可变：原生KV分别保存notice、read、resolved三个事实，同一数据库持久化，无第二套通知数据库或任务状态。

- 打开全文预览才标记已读。未读标记与未读数量随之清除。
- 已读不等于问题解决。requiresAction且未resolve的通知仍计入Needs action。
- 只有模块自身显式resolve才解决人工事项；GUI阅读接口不能替模块确认。
- 模块停止或下次未装配时，历史通知仍可读。重启不能因此重做AI任务、重发外部消息或重新打开连接。
- 按创建时间倒序、稳定id处理同一时间的分页边界；支持all/unread/attention筛选。原生SQL仅读取自己的通知键范围，不枚举其他插件数据。

本轮公共通知页提供独立计数和预览，不声称已经替换所有旧业务通知或完成全局通知铃铛。QQ任务首轮/最终回执继续沿原来的原生输入归属和持久发送回执，不改成系统通知调度。

## 按需监控

模块资源可以提供metrics(signal)，返回最多64个有限数值：id、label、value、unit。单位支持percent、bytes、milliseconds、count；不提供回调时明确unsupported，不伪造零占用。提供方必须遵守取消信号，停止自身采集。

原生服务只响应显式读取；相同模块并发读取合并为一次，快照至多每秒更新一次。模块停止会取消采集。没有全局定时器、全进程扫描或QQ登录前提。

GUI仅在选中模块的监控面板存在、连接可用且文档可见时约每秒读取。关闭监控、离开设置、断开连接、隐藏窗口时停止定时器并取消在途读取。恢复可见后按需继续。元数据变更使用原生RPC changed事件，不后台轮询状态。

本轮验证的是可用的公共指标入口、生命周期与可见性规则，真实硬件/进程采集器尚未迁入。后续设备或性能模块接入回调即可，不在核心加具体设备分支。
