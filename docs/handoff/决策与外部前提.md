# 已接受决策与后续外部前提

## 已接受决策

| 编号 | 决策 | 对实现的约束 |
| --- | --- | --- |
| D01 | 接入一整套会话后端 | 不要求上下文、压缩、工具和队列分别安装为独立插件 |
| D02 | 所属后端拥有执行队列 | 宿主只维护转交和通知账本，不再认领或启动同一会话的下一任务 |
| D03 | OpenCode 与原生 Codex 后端同级 | Codex 后续可以保留原线程、账号、上下文、工具和压缩，不塞入 OpenCode 工具循环 |
| D04 | 普通 API 由完整后端使用 | Agent2API 可以作为一个 API 地址，不能成为所有后端的必要依赖 |
| D05 | 本阶段只建设地基 | 不接管旧任务，不重组业务模块，不默认更改正式启动入口 |
| D06 | 模块统一放在 modules | `modules/<module-id>/` 是一个完整包；测试后端放在 tests/backend_fixtures |
| D07 | 默认使用 Python 做宿主 | 原生 SDK、语言和数据结构留在后端内部；不把全部程序强制改成 Python |
| D08 | 状态来自真实接纳和事件 | 网络成功、排队、已应用、执行结束和通知成功不得混为一个状态 |
| D09 | 新仓库可以独立开发 | 旧工作区路径只是参考；前两阶段不以旧源码或私人运行环境作为先决条件 |
| D10 | 保留已确定的界面方向 | 本轮不做整套 UI 重新设计；真实旧客户端集成需要相应代码基线 |

这些决策来自当前重构要求。后续用户明确改变方向时，先更新本表及受影响的契约和任务，避免相互矛盾的说明继续同时生效。

## 尚需核实或提供的前提

| 编号 | 内容 | 影响范围 | 处理方式 |
| --- | --- | --- | --- |
| E01 | 旧客户端源码按本地只读基线使用，不放进公共仓库 | P3 的真实页面适配与实机验收 | 读取不提交的 handoff.local.json；本机已配置，换机器需重新定位，不要求上传源码 |
| E02 | 新环境中 OpenCode 2.1.4 的运行时要求 | P2 | 核对包 metadata、类型和实际启动；本仓库不声称当前已经安装 SDK |
| E03 | 原生队列调序等可选方法能否按锁定版本实现 | P2 及未来后端 | 逐项验证后声明，不能仅因示例中有某个能力就显示按钮 |
| E04 | 真实模型服务的可用连接与测试授权范围 | P2 的真实上游验证 | 隔离 API 夹具先完成；真实服务测试另记请求数和用量，不借用本机凭据 |
| E05 | Codex 原生系统与旧队列的数据迁移 | 地基完成后的另一阶段 | 本阶段只验证另一套整后端夹具，不要求接入实际 Codex |
| E06 | 项目整体开放许可未选择 | 后续采用或分发外部代码 | 保留外部来源许可，不能假定公开仓库等于授予任意再许可；当前不擅自添加项目许可证 |

E01、E04、E05 不能成为跳过 P0/P1 的理由。SDK 方法不适配时，先在完整后端适配范围内解决；需要升级基线时记录原版本、缺口和兼容验证，不直接使用未锁定的 latest。

## 接手时需要继续收口的契约细节

本轮仅补交接资料，不修改既有 JSON Schema 或增加后端接口。以下问题要在所属实现任务中同步规范和测试后再关闭，不能默认为已经解决：

| 编号 | 现有细节 | 所属任务 | 收口要求 |
| --- | --- | --- | --- |
| C01 | 文档说原生 ID 不透明，但事件 Schema 部分原生输入/运行 ID 采用宿主正则 | P0-01 | 决定有界原生引用或稳定映射方案，兼顾原生身份保留与校验，不改变后端机制 |
| C02 | 文档允许大型正文和附件引用，但缺少完整读取操作及能力约束 | P0-01 | 统一引用作用域、读取方式与大小边界；留在整套后端门面，不另拆资源插件 |
| C03 | 文档包含消息顺序、版本替换和增量描述，当前 Schema 仅覆盖部分字段 | P0-01 | 确定 V1 的公开更新形状和稳定顺序，防止两种控制器各自猜测 |
| C04 | stdio framing、传输超时及积压上限只有实现建议 | P0-02 | 把默认值与错误行为固定到传输测试，超时不能自动取消任务 |
| C05 | 实例 ready 与模型连接 available 尚无完整握手数据形状 | P1-02 | 管理门面与生成能力分开，缺凭据不阻塞宿主启动 |

原生上下文、公开历史和事件世代的所有权已经明确；上述是边界契约的落地细节，不是重新拆分整套后端的理由。
