# 当前决策与待验证边界

以下决策覆盖旧路线；旧内容仅作 [归档](../archive/python-host-plan/README.md)，不得混作当前实施指令。

| 编号 | 已确认决策 | 约束 |
| --- | --- | --- |
| D01 | 完整OpenCode应用作为二次开发基座 | 不再建设独立Python会话宿主后嵌入OpenCode |
| D02 | 原生交互、数据访问、会话、Inbox、数据库和压缩整体优先复用 | 不自行重写发送/队列/历史状态机，不建立竞争会话库 |
| D03 | 助手视觉与有限动效保留 | 在原生组件和桌面壳上改，不复制旧交互控制器 |
| D04 | 移除项目文件树及文件操作能力 | 包括项目工具和通用命令绕行；不仅隐藏文件界面 |
| D05 | 保留内部持久化和受控附件/业务文件服务 | 去文件工具不等于删除数据库、缓存、配置、迁移及附件 |
| D06 | 旧助手是能力探索经验 | 本地只读盘点当前有效规则和缺陷，不整体搬迁旧架构或私人数据 |
| D07 | Codex保留完整原生会话机制 | 同级入口，不模拟成无状态API，不嵌套另一层Agent执行；接入需先验证 |
| D08 | QQ仅为可选转发能力 | 不作为启动条件，不拥有执行队列，通知失败不重跑任务 |
| D09 | 原生扩展优先，缺口才最小产品补丁 | 不强迫业务拆成大量小插件，不偷偷复活旧宿主 |
| D10 | 基座先稳定，业务逐项接回 | 重负载能力可独立服务；研究、下载、设备、播放器不同时大迁移 |
| D11 | 原生产系统和数据不自动切换 | 独立ID/目录/端口，迁移与回退按会话核对，旧源码不上传 |
| D12 | 旧P0是历史参考 | 已完成事实保留在归档，新计划重新验收，不继承虚假完成状态 |
| D13 | 整体保持核心框架＋插件 | OpenCode作为核心基础，助手业务作为完整能力插件；依赖/运行时不混作功能插件，不建立外层宿主或把业务全部写进核心 |
| D14 | 二次开发不得偏离既定职责 | 每次改动核对层次、原生入口、状态所有者及依赖方向；插件只经公共接口/展示位置接入，不接管全局发送或竞争调度 |
