## 已可运行的模型发现入口

在 `opencode/packages/im-assistant` 中，用锁定 Bun 执行 `bun run src/cli.ts models`，从标准输入传入 JSON：`baseURL` 是 API 根地址（例如包含 `/v1`），可选 `apiKey` 是连接密钥。不要把真实密钥写进命令行、公开配置例子或测试记录。

程序请求该根地址下的 `/models`，返回去重后的模型 ID 与 `generationVerified:false`。目录查询不选择默认模型、不调整现有会话或排队输入，不假设上下文上限、价格、思考能力或生成可用性。目录成功和生成成功必须分别验收。

入口按需运行，无后台轮询、自动重试或页面跳转。连接超时 10 秒；不跟随重定向传递凭据。HTTP 错误只显示状态码；HTML/非法 JSON 显示 API 地址诊断，不回显响应正文。非法 URL 不回显原始地址。`Storage.prepare` 仍只准备助手私有目录，不借用旧软件或普通 OpenCode 的凭据。

验证：`python -m tools.provider_discovery_smoke` 启动自己的本地兼容 API，实际调用产品 CLI 查询目录，确认未发生生成；随后用发现的模型 ID 在真实管理模式原生 HTTP/SQLite 会话生成一次，并核对保存的 input=10/output=4。所有请求均为本地合成测试，不能据此声称 Agent2API 的真实账号已经连接或桌面设置界面已完成。

## 已核对的统计边界

- 原生 `core/src/session/usage.ts` 将缺失或非法 token 转为 0；`TokenUsage.Info` 的 input 是非缓存输入，output 是可见输出，reasoning 和 cache.read/write 单列。直接相加时避免把 reasoning 或缓存重复计入。
- 原生 `record` 优先使用端点 cost，包括真实的 0；未报告 cost 时回退到模型目录价格。新记录已在 tokens.provenance.cost 保存 reported/catalog/unavailable/mixed 来源；旧记录缺省仍未知，不能将数值统一显示成实际扣费。套餐参考统计不能由目录价格冒充账单。
- 原生 `core/src/session/stats.ts` 提供时间区间汇总，区间为 from 包含、to 不包含；按时区归组，内部按 31 天窗口查询。今天/最近7天/累计应调用同一接口，按需获取，不能再建一套 token 账本或空闲轮询。
- 仅凭已归零的历史数据，无法追溯上游当时是没报告还是报告了 0。新增可选 tokens.provenance 在归零前保存各字段是否由原生适配器提供有效计数；合并保守处理，含旧数据则仍未知，不能推算成确定值。压缩和上下文容量继续用原生模型/会话信息，不固定写成 1M。
