# 会话模式的能力边界

本阶段沿用 OpenCode 原生 Session、Inbox、客户端状态、历史、上下文和压缩；没有另建会话宿主或队列。产品包 `packages/im-assistant` 只选择通用宿主预设、管理位置和启动方式，Core/Protocol/Server 不依赖助手业务包。

## 实际执行限制

`RuntimePolicy` 是宿主创建服务时传入的可信配置，不是模型提示词、用户可覆盖的权限规则或会话字段。助手使用 `session-location`，只允许该位置及原生私有配置位置成为 Location；关闭仓库发现、项目与全局指令发现、系统配置扫描和文件监视。内部数据库、配置、缓存、草稿及附件存储继续使用原生文件系统服务。

- 模型工具目录与快照为空；直接构造工具调用、放宽会话权限或注册工具也不能执行。Code Mode 和原生通用命令同样禁用。
- 原生 shell 调用和项目 snapshot/diff/restore 有执行侧限制；HTTP 只开放明确的会话、历史、Inbox、模型、认证和附件媒体能力。
- 项目文件、Git/worktree、终端、通用 RPC、命令型认证、MCP 和外部插件加载相关 API 拒绝调用。返回 JSON 错误，不以隐藏按钮代替执行限制。
- 后端不发现/激活外部或 SDK 注入的任意代码插件；动态提供商只接受内置适配器路径，仍支持内置 OpenAI 兼容适配器配置自定义 API 地址。
- 配置中的项目指令、MCP、外部插件和 `{file:...}` 替换不能恢复项目文件能力。受控凭据仍由原生配置/凭据系统管理。

这是应用能力裁剪，不是操作系统沙盒。运行应用的本机用户仍能修改源码和可信启动配置；不能宣传为隔离任意本机恶意代码。

## 原生界面与附件

桌面在窗口 bootstrap 中传递会话模式；网页由原生 WebUi 宿主在 HTML 中声明同一模式，加载时同步读取，不增加初始化网络等待。`/api/info` 的 `capabilities.experimental.projectWorkspace` 同时供 API 客户端查询。Protocol 修改后使用原生 `packages/client` 的 `bun run generate` 生成客户端，没有手改生成代码。

助手不加载文件树、终端、review 等 GUI 插件，也不展示项目/工作树选择、项目路径菜单及相关设置入口。原版模式默认保持原行为。项目操作与 shell 快捷键不会通过键盘重新进入。

保留原生输入框、发送、接收、排队、撤回、消息顺序和历史控制。附件经用户选择或粘贴后，使用原生草稿 blob 与消息字节上传；不再把文本文件上传到可任意指定路径的文件写入 API，也不把本地 `file:` 路径交给模型。单附件上限沿用原生 20 MiB；原生图片预览保留。历史、媒体与 JSON 会话导入导出仍由原生数据库接口处理。

后续下载等业务文件能力必须由完整能力插件提供受控操作，不能重新开放通用文件 API 或靠会话权限解锁被移除的工具。当前不宣称插件市场、Codex、QQ、研究或其他旧模块已经迁入。

## 验证和后续接手

`python tools/run_runtime_checks.py --task R1-02` 驱动原生单元、真实 HTTP、合成模型、生产网页构建/浏览器与私有 Windows 桌面重启。拒绝调用的验证使用临时哨兵文件、外部插件/MCP 标记和合成提供商，没有真实账号或模型调用。内部数据、运行日志和原始截图均不提交。

性能记录使用相同 65 字符输入的生产构建；单次样本用于核对本次裁剪，没有统计意义，不据此宣称提升百分比。上游两个压力基准的准备/旧存储断言失败也保留在本地诊断记录，没有计为通过。原生会话交互的专门验收仍属于 R2-01，不能以 R1 能力裁剪代替 A11-A16。

状态以 `progress.json` 和脱敏验收摘要为准。不要使用上游桌面 `script/build.ts` 下载 dev CLI 作为产品基线；当前使用已锁定源码的 `bun x electron-vite build` 构建桌面 bundle，由产品入口连接锁定源码 CLI。安装包、更新和正式切换另行验收。

## QQ图片入口

显式NapCat images能力只读取认证平台返回的图片base64，并核对内容标识、编码、签名和上限。交给原生受控附件及整套后端inline图片字段；不打开平台路径/链接，不新增文件或shell工具。图片字节仅进入原生消息存储，QQ元数据不存正文、附件字节或模型上下文。未启用、失败和不支持的引用附件整体拒收并返回对应原消息的单次提示；普通文件、音视频及图片以外能力不因此开放。
