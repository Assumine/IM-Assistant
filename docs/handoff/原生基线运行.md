## 安装和验收

在新仓库根目录运行：

```sh
python -m pip install -r requirements-dev.txt
python -m tools.setup_native_baseline
python tools/run_runtime_checks.py --task R0-01
python tools/validate_design.py
```

安装器限定 Windows x64，校验已锁定的 Bun 1.4.4 与 Node 24.22.2 官方 ZIP，放入忽略的 runtime/tools/；只改子进程环境，不改系统 PATH。依赖使用原版 `bun install --frozen-lockfile`。Electron 44.9.1 来自原锁定依赖，Chromium 由原版 Playwright 安装。网络下载和运行日志均不提交。其他平台需要另核对工具链，不能直接使用 Windows 二进制。

验收入口每次真实执行，不以旧报告代替运行：

| 范围 | 原生命令/检查 | 边界 |
| --- | --- | --- |
| Core | packages/core 下 bun run test，6 个原生 session 测试文件 | 输入、执行协调、视图、压缩；92 项 |
| 桌面存储 | packages/desktop 下 bun test --timeout 30000 src/main/storage | 原生 SQLite、迁移、草稿、重开；30 项 |
| 前端单元 | packages/app 下原生 queue.test.ts、list.test.ts | 19 项 |
| 网页 | packages/app 下 bun run test:e2e:built -- e2e/regression/session-queue.spec.ts e2e/regression/timeline-history.spec.ts --workers=2 --retries=0 | 原版构建及真实浏览器；45 项。原测试使用模拟 HTTP，不冒充真实后端 |
| Windows bundle | packages/desktop 下 bun x electron-vite build | 原生 main、preload、renderer；不是安装包签名或分发验收 |
| 真实 API | tools/native_api_smoke.py | 原生服务/HTTP/SQLite；立即入队、同 ID 首次接收生效、撤回、重启恢复；本地模拟模型生成并保存真实历史 |
| Windows 启动 | tools/native_desktop_smoke.py | 原生 Electron 窗口首次启动与重开，读取真实 renderer 就绪状态；不把 DOM 检查冒充截图视觉验收 |

原生命令统一经 tools/native_baseline.py 提供隔离 HOME、XDG 和临时目录，避免读取用户模型凭据。工具只负责编译和测试，不是新的应用宿主、调度器或会话库。原生测试日志和运行回执在 .reports/native/，总验收回执在 .reports/runtime/R0-01.json。

## 本轮发现与限制

- 隔离 Windows HOME 需要 Documents 目录，否则原版 Electron 的 app.getPath('documents') 会失败。测试环境创建该目录，不补丁修改原版应用。
- 原版开发模式的 isolated server 固定使用 3084 并监听 0.0.0.0；验收开始前要求端口空闲，并在结束后通过指定私有注册文件调用原版 Service.stop 清理。不能强停其他占用者，也不能把这一开发模式作为产品发布默认值。R1 必须选择助手自己的身份、数据根和仅本机服务端口。
- 原版 Electron 的 CDP 截图在窗口被遮挡时可能等待绘制超时；本轮桌面验收使用原生窗口及 renderer 就绪检查。网页回归使用真实 Chromium；完整视觉验收属于后续换肤阶段。
- 本地模拟模型只用于覆盖生成→原生历史→重启恢复，不代表接通用户真实 API，也不能据其合成 token 声称真实用量或费用。
- 未安装生产安装包，未切换旧助手，未导入用户私库，未设置开机启动，QQ/Codex/研究业务插件尚未迁入。原生项目树及文件工具仍存在，R1-02 才移除。R1-01 已增加独立助手身份与存储，见助手入口与隔离.md。

后续修改上游文件必须写入 upstream/patches.json，记录目的、文件、回归与上游版本；相应扩展源码校验为“原始清单＋明确补丁”，不能为通过验收直接删除原始校验。
