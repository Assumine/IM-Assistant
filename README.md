# IM-Assistant

基于完整 OpenCode 应用二次开发的个人助手。尽量复用原生前端交互、客户端数据访问、会话服务、Inbox、历史、数据库、上下文和压缩；裁剪项目文件树及文件操作能力，换上助手的视觉样式和有限动效，再逐项接回需要的个人助手能力。

已导入并锁定 OpenCode v2.2.3 完整源码。R0、R1、R2及R3-01隔离可行性已通过，完成 A01-A22（6/10任务）；下一项是QQ薄转发。通用后端设置、可选认证、原生线程标签和运行/队列视图已实现，可从设置将历史打开到主区域，支持切换、刷新恢复和关闭重开。新建页另有明确选择整套后端并创建或打开原生会话的入口，保留原 OpenCode 草稿。主页可展开其他后端的原生会话分组，按需读取列表、分页并直接打开原始会话。队列复用原生界面，可显式引导、撤回和排序，并按原轮次停止执行；文本发送、草稿保留和生命周期消息更新已接入；队列原位编辑和确认撤回后恢复到输入框已接入；直接引导和活跃连接的逐段文本显示已接入；人工提问面板与后端链路已通过隔离验证；产品启动已支持显式下次启用；Codex 默认关闭，真人账号及生产切换未验收。当前进度以 [交接记录](docs/handoff/最近交接.md) 和 progress.json 为准。另有14处既有 E2E 类型诊断尚未通过。整体保持核心框架＋插件，旧 Python 宿主路线和49项测试仅作历史参考。

## 主要边界

项目文件树、文件编辑/读取/检索/补丁及通用shell等编码能力从助手产品移除；应用内部数据库、受控附件和明确业务文件处理仍保留。去掉文件能力不意味着删除所有磁盘持久化。

OpenCode普通API会话沿用原生执行和队列。Codex整套原生会话作为适配能力保留线程、账号、上下文和压缩，不套入另一层模型循环。QQ仅是可选转发入口，不影响应用启动。

服务层已提供通用的可信整套后端模块生命周期：独立加载、失败隔离、随应用作用域断开连接。Codex模块已在隔离服务启动链路验证，专用凭据目录补上Windows权限保护与漂移拒绝；产品CLI已支持独立资料初始化和显式下次启停，并通过正式R3-01隔离可行性验收；真人登录、本轮桌面与生产切换仍未验收，默认不启用生产后端。

旧助手保留在本地，提供能力探索、现行规则和缺陷经验，不整体搬入旧宿主、队列及私人数据。研究、下载、设备、播放器和小羊等按后续模块阶段逐项接回。
