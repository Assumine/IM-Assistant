# IM-Assistant

基于完整 OpenCode 应用二次开发的个人助手。尽量复用原生前端交互、客户端数据访问、会话服务、Inbox、历史、数据库、上下文和压缩；裁剪项目文件树及文件操作能力，换上助手的视觉样式和有限动效，再逐项接回需要的个人助手能力。

已导入并锁定 OpenCode v2.2.3 完整源码。R0至R5基座计划已完成隔离验收，共10/10任务、A01-A36（36/36）；已具备逐会话迁移与回退方案，生产入口、自启及真实账号尚未切换。助手模式已接入固定图标导航、紧凑布局、原生字体/DPI及新消息一次入场；网页、真实Chromium和Windows原生窗口分别有运行证据。QQ默认关闭，真实账号与发布仍未验收。通用后端设置、可选认证、原生线程标签和运行/队列视图已实现，可从设置将历史打开到主区域，支持切换、刷新恢复和关闭重开。新建页另有明确选择整套后端并创建或打开原生会话的入口，保留原 OpenCode 草稿。主页可展开其他后端的原生会话分组，按需读取列表、分页并直接打开原始会话。队列复用原生界面，可显式引导、撤回和排序，并按原轮次停止执行；文本发送、草稿保留和生命周期消息更新已接入；队列原位编辑和确认撤回后恢复到输入框已接入；直接引导和活跃连接的逐段文本显示已接入；人工提问面板与后端链路已通过隔离验证；产品启动已支持显式下次启用；Codex 默认关闭，真人账号及生产切换未验收。当前QQ阶段为qq-plugin-migration-v1，任务与验收独立于基座计数；当前入口为Q1-01。当前进度以 [交接记录](docs/handoff/最近交接.md) 和 progress.json 为准。原有14条独立E2E类型诊断已清理；基座发布验收入口为R5-01，固定对应原源码版本。整体保持核心框架＋插件，旧 Python 宿主路线和49项测试仅作历史参考。

## 主要边界

项目文件树、文件编辑/读取/检索/补丁及通用shell等编码能力从助手产品移除；应用内部数据库、受控附件和明确业务文件处理仍保留。去掉文件能力不意味着删除所有磁盘持久化。

OpenCode普通API会话沿用原生执行和队列。Codex整套原生会话作为适配能力保留线程、账号、上下文和压缩，不套入另一层模型循环。QQ仅是可选转发入口，不影响应用启动；当前已隔离验证显式目标、去重、撤回及原始消息反查，普通Session支持待办追加、当前输入护栏续接和已结束输入的关联后续，Codex当前任务引用通过原生期望轮次校验，已结束输入可建立独立的关联后续并进入原生队列。跨会话引用已接持久确认提示和引用式/confirm、/cancel交互，确认后使用原目标，当前绑定不变。控制命令已支持显式授权后的列表、绑定、队列/状态读取和按固定输入撤回，重复写命令不重做；支持引用已确认发布的清单进行序号选择。认证OneBot通道已接应用级资源所有者和产品启动，提供默认关闭的本机配置命令，并通过真实产品进程与本地协议端联调；控制回执已接持久发送意图/回执及确认后的清单发布，重复与重启不重复发送；普通Session及Codex首轮/最终公开回复已按原生输入归属接通，Codex支持重启核对补发和明确终态通知；QQ可显式启用NapCat登录历史补收，按已观测断点接入同一原生队列；可单独设置任务机器人账号下次启停，账号故障及绑定/回执互相隔离；小羊另作独立可选聊天插件，尚未迁入；实际QQ连接、未引用清单的序号及其余控制命令仍在实现，Codex待办追加仍受原生接口限制，尚未启用机器人账号。

服务层已提供通用的可信整套后端模块生命周期：独立加载、失败隔离、随应用作用域断开连接。Codex模块已在隔离服务启动链路验证，专用凭据目录补上Windows权限保护与漂移拒绝；产品CLI已支持独立资料初始化和显式下次启停，并通过正式R3-01隔离可行性验收；原生Windows窗口已通过隔离验收；真人Codex登录及生产切换仍未验收，默认不启用生产后端。

旧助手保留在本地，提供能力探索、现行规则和缺陷经验，不整体搬入旧宿主、队列及私人数据。研究、下载、设备、播放器和小羊等按后续模块阶段逐项接回。

公共能力已接原生应用Scope、动态RPC和GUI设置，可读取实际模块状态、停止本次运行、阅读系统通知；已读与待人工处理独立。监控只在可见面板按需读取，不后台扫描硬件。真实硬件指标提供方尚未迁入；助手主题已接入原生设置。接入方式见[公共能力接入契约](docs/handoff/公共能力接入契约.md)。
