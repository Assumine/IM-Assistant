# QQ 可选转发入口：当前为第一段隔离切片

`createPortal({ storage, session, policy })`消费已认证OneBot通道交来的结构化事件，调用原生Promise客户端的Session/Inbox接口。它不登录QQ、不监听网络端口、不轮询、不创建会话/任务库，不负责挑选或执行下一条任务。生产产品尚未装配此入口，也没有使用旧账号、绑定或历史。

当前支持：

- 分离机器人、群/私聊、实际成员和消息ID；群必须同时满足允许群、允许成员和@任务机器人。其他机器人（包括小羊）、机器人自己及发出事件不进入任务链。
- 只消费明确支持的text/at/reply分段，保留正文空白和用户字面标记。图片/表情等未实现输入整体返回unsupported，不丢弃附件后只转文字，也不解析字符串中的CQ代码。
- `/list`、`/codex list`及大小写形式先分类为控制请求，返回给控制分发层；不因会话忙碌而作为AI任务。当前只做分类，没有实现这些远程命令处理器。
- `bind`为可信宿主控制函数，验证原生Session存在后保存绑定。它不承担远程身份认证；未来传输层必须先验证命令权限。绑定变化不移动既有输入。
- 普通消息直接用稳定原生输入ID调用Session.prompt(queue)，不建立QQ待办队列。公共插件KV的原子insert只冻结来源/目标/摘要元数据，不保存正文、执行状态或模型上下文。
- 重复消息查原生pending或已交付user记录；内容冲突拒绝。首次交付结果未知且无原生证据时保留uncertain，不重新发送。重新绑定和重启后仍查原目标，不误投当前会话。
- 撤回只调用原生Inbox.cancel，不调用interrupt或发送“停止修改”。撤回先到时保存同来源/作者墓碑；已交付输入保持不变。原生取消竞争或故障返回uncertain，不伪报成功。
- `linkReply`仅在外发实际收到消息ID后由可信宿主调用，可将AI回复/回执关联到原始输入；冲突不可覆盖。当前未实现外发，因此不制造发送成功或自动通知。

已知引用目前返回blocked：同会话引用需要原生“条件引导/待办追加”契约，跨会话引用需要一次确认。没有把这些缺口改成另发一个无关任务，也没有用旧队列控制器绕开原生接口。未知引用作为普通新输入时明确返回unresolved。Codex整套后端目标、附件、首轮/最终引用、离线通知补发核对及提示撤回均待后续实现；小羊的现有聊天规则不由此模块接管。

验证：

```sh
python -m tools.qq_portal_smoke
```

32项规则/权限用例、8项原SDK实例回归，以及真实SDK＋HTTP＋SQLite的10项检查。真实原生模型流在首token前被本地夹具暂停，检验QQ与桌面共用Inbox、8份并发去重、撤回、失回执核对、绑定冻结、重启不重放和无QQ插件时核心正常。模型请求仅本机合成，没有外发QQ消息。

助手模式继续禁止普通SDK插件、实例插件、配置目录扫描和任意路径加载。新增的SDK `trustedPlugins`只由可信程序代码显式贡献，通过原生插件生命周期加载；不能放在用户消息、模型工具或项目JSON中。公共storage.insert按插件命名空间原子首写，Promise和Effect接口一致。不要在每个会话实例的setup里重复登录同一个机器人；实际传输连接生命周期和产品装配尚未接入。

`upstream/qq-checkpoint.json`仅记录partial_verified，publication=disabled。正式`tests/rebase/test_r3_02.py`尚未实现，A23–A26不计完成；本阶段不代表真实机器人已连接或可发布。
