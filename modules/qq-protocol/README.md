# QQ 协议依赖

普通依赖库，不是第三个业务插件，也不单独启动宿主、登录界面或任务执行器。公开入口为 `src/index.ts`（package exports 的 `.`）；任务转发和独立聊天均使用此入口，不反向导入任一业务插件的私有文件。

## 所有权

调用方创建连接并负责在自身 ApplicationModule 结束时 close。每个账号在同一原生应用进程内只能有一个连接所有者；重复打开返回 `unavailable/account-in-use`，不连接、不共享事件、不抢走已有账号。不同账号各自鉴权和验证身份。关闭、鉴权失败或断线释放本连接的所有权，不能释放后来创建的连接。

这不是跨进程账号锁。独立启动两套应用、自动重连、登录和同账号多业务分流尚未实现；业务应默认使用不同机器人账号。未知发送回执不自动重试。

## 当前公共能力

`openOneBot(options, callbacks)` 提供 ready、状态副本、close、带引用的纯文本发送、已确认输出的撤回，以及受限来源读取、NapCat 历史和图片元数据读取。回调事件保留结构化协议，不将用户文本解析为 CQ。图片只接受内容标识，不打开返回的路径或 URL。调用方仍负责自己的授权、来源指纹、历史覆盖证明和已发送输出证明。

`send(scope, text, quoteID)`保持任务转发的“引用＋文本”契约，引用ID必填。`sendMessage(scope, parts, quoteID?)`支持聊天的结构化文本、群成员@和明确提供的inline图片，引用可选；群@不支持all，私聊不接受@。整个parts先校验再发送，CQ文本不解析为协议，不开放任意OneBot动作。

`decodeImage`对认证get_image返回的base64执行预算、图片签名和内容ID哈希校验，路径/URL一律不读取；任务转发与聊天共用该校验。`inlineImage`只接受明确提供的data:image字节及匹配的MIME，不打开文件路径或远程URL。成员是否允许被@、图片是否允许读、表情资产是否获授权仍由调用业务负责。

账号寻址 Source/Scope 不包含任务、绑定、人格或记忆。协议不依赖 OpenCode；业务插件各自通过原生公共客户端接入会话、Inbox、历史和压缩。两个消费者的状态与连接相互隔离，业务策略不放入协议库。

## 验证

Q1-01原证据固定在当时的提交，包含9项消费者隔离用例及10次额外重复。当前`tests/modules/test_q1_03.py`编排13项本库测试（其中4项媒体/结构化发送另重复10次）、类型检查、聊天链路及原有QQ产品回归。转发已有协议契约测试继续经兼容入口验证同一个实现；共享loopback夹具位于本库test/fixture，转发仅补充自己的策略数据，不再维护第二个协议服务夹具。

本库在modules内是普通源码依赖，不属于上游36个工作区。验收因此额外检查本库和转发的类型，不把上游check通过当作已覆盖所有模块。
