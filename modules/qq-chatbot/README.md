# QQ 聊天附属插件

Q1-02实现独立ApplicationModule、原生会话、人格指令和成员归属。它可以在没有任务转发模块时运行。当前为聊天内核接入，不是已经上线的QQ聊天服务：原始QQ事件策略、公开回复、回复开关、图片/@属于Q1-03；产品配置及默认关闭的正式装配属于Q1-04。没有导入旧小羊的人格文件、私人历史或真实账号。

## 原生所有权

公开入口src/index.ts提供createChatbotModule、createChatSessions和类型。createChatbotModule同步提供原生ApplicationModule及receive入口，异步检查原生模型目录和Agent后接收入站；ready只表示首次初始化结果，当前状态以原生模块目录为准。一个账号的模型或Agent无效时只停用该账号；其余账号可用时整体health为degraded。

配置显式提供受管理的绝对Location、账号、原生model引用、可选agentID以及persona.name/prompt。缺省Agent为原生build，缺省模型variant按原生Session.Info约定固定为default。人格使用原生API-managed instruction entry，不修改全局Agent、Provider或其他会话。模型、上下文限制、历史、压缩及用量全部由原生实现持有。

会话按“插件＋机器人账号＋私聊对象／群号”隔离。群成员共用该群的原生Session，每条模型输入是qq-message JSON，包含实际sender.id、可选显示名及正文；显示名仅作标签，不改变身份。私聊、不同群及不同机器人账号使用不同原生会话。配置或已保留会话的身份、模型、Agent、权限发生不一致时拒绝静默接管。

默认Session权限deny-all，不继承任务控制、研究派发、Codex绑定或通用操作能力。receive接收的是经本插件入口授权后的结构化消息；它不解析任务命令，也不承担任务转发的绑定逻辑。消息读取和回复资格将在Q1-03由本插件单独判断。

## 重复消息与生命周期

插件KV只保存身份、会话映射及不可变消息指纹，不保存消息正文、模型上下文、执行状态或第二套队列。首次输入交给原生prompt/Inbox。同一消息的并发转交只合并正在进行的接纳请求，不等待AI完成；请求结束立即释放。

已有指纹的重投只核对原生Inbox或历史，绝不重新发送prompt。原生普通prompt允许同ID撤回后再次入队，所以不能把再次提交当作重复消息核对。消息已撤回、原生结果不存在或未知时返回uncertain，不能声称已执行，也不会自动重放。显示名变化不修改旧输入或转移成员身份。

已有绑定的原生Session被删除后不自动创建替代会话；人格/模型发生冲突时也不覆盖历史。显式更换配置与重置上下文需要后续受控迁移入口，当前收到此类不一致会拒绝接纳。模块停止后拒绝新输入、结束自身接纳资源；已交给原生的推理和待办继续由原生负责。

## 验收范围

运行python tools/run_runtime_checks.py --task Q1-02。实际HTTP、原生应用Scope、SQLite、合成模型及真实任务转发模块覆盖群成员、跨群/私聊/账号隔离、重复输入、撤回重投、删除历史、模型故障、停止、重启、压缩和用量。人格验证证明指令进入真实模型请求及压缩后保留，不代表合成模型测试已经评价真实小羊的角色表现。

API-managed JSON会话指令条目作为通用原生能力接入宿主，文件和URL标记按字面文本处理；不打开项目指令发现、文件路径、Shell、MCP或外部插件。原文件边界和受控附件另跑真实产品回归。日志和合成数据库留在忽略目录，公开证据只有源码指纹和验收结果。
