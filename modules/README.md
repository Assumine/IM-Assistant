# 助手能力包

能力包统一放`modules/<module-id>/`，以完整OpenCode应用为基座，优先复用原生服务端、插件KV、动态RPC、GUI和命令扩展。依赖、运行时和驱动不是功能模块；不为原生上下文、压缩和工具循环各造一个必装扩展。

整体保持核心框架＋插件。插件可包含完整业务、界面和独立服务，但只经公共接口和展示位置接入，不覆盖全局发送/队列，不读取其他插件私有数据，不让主程序依赖QQ、网关或某一业务启动成功。

## 当前能力

| 能力 | 职责与当前边界 |
| --- | --- |
| codex-native | 整套原生Codex后端，保留线程、账号、上下文、压缩和原生执行。R3-01隔离可行性验收完成，默认关闭；真实账号与安装包未验收。 |
| qq-portal | 可选任务/会话转发、显式目标、来源/引用映射和发送回执。R3-02隔离链路验收完成，不拥有执行队列。账号故障、开关、绑定和回执隔离；配置启停下次服务启动生效。 |
| qq-chatbot（接入中） | 独立ApplicationModule、原生会话、人格和成员隔离；已接认证QQ通道、只读观察/回复开关、参与策略及结构化图片/@。仍只在隔离装配验证，正式产品配置为Q1-04，不作为qq-portal的人格模式。 |

`qq-protocol`为两类QQ业务共用的普通协议依赖，不作为功能模块注册或展示。任务转发和聊天均使用其公共入口；它提供认证连接、账号寻址、内容校验和结构化发送，不接管授权、绑定、人格、模型或队列。一个进程内同账号不能被两个消费者同时打开；跨进程租约和聊天的正式产品装配仍待后续验收。使用边界见[协议依赖](qq-protocol/README.md)。

QQ回环已覆盖普通Session及整套后端、当前输入调整、历史后续、跨会话确认、补收、图片、首轮/最终归属和排队提示撤回。真实QQ、自动重连、一般文件/音视频与部分控制命令未完成；Codex待办追加因缺原生原子接口仍明确阻止，不能私造第二套Inbox。

## 公共接入位置

通用ApplicationModule由原生应用Scope持有；可信延迟Loader读取配置，不阻塞核心启动。模块可报告health、发布自身通知、提供可取消的按需metrics快照。原生GUI设置提供模块实际运行状态、当前运行停用、通知全文及已读和待人工处理的分别计数。监控面板关闭/隐藏即停止采样；实际硬件采集器尚未迁入。

接入细节见[公共能力接入契约](../docs/handoff/公共能力接入契约.md)。Codex继续走已有整套ConversationBackend扩展，不复制成ApplicationModule影子后端。QQ聊天的账号与权限边界见[QQ接入与附属机器人边界](../docs/architecture/QQ接入与附属机器人边界.md)。公共框架完成不代表研究、下载、设备、播放器或小羊业务已全部迁入。
